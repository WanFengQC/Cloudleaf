# Round 29 词典运行时生命周期

设置中心在共享配置目录读写独立的资源修订记录。资源修订保留基础、补充两个选择槽及各自的上一选择。后台保存前校验所选字节与固定来源身份，发布前校验回退目标。路径损坏的当前版本不能覆盖原有回退记录。一次原子替换只写完整新配置。当前进程保留已加载快照直到新代成功应用。资源选择、后台准备和宿主应用分别呈现。Round 28 的输入偏好 schema 和热应用继续使用原入口。

基础资源由本仓库固定的已批准内容身份准入，限定具体 TSV、来源和许可版本。补充资源使用不同身份，保持研究状态，只在明确启用后进入组合索引。来自同一来源、拥有相同稳定 ID 和字段的行可以共享；同 ID 不同事实拒绝发布。不同来源、不同读音继续留存在索引内；候选正文去重沿用搜索。用户词库仍是现有私有叠加层，源资料和学习代次独立于资源配置。

后台完成字节限额、SHA、结构、索引和模型绑定。指定相同启动快照时保留模型；旧的绑定不能用于不同词典索引。宿主需要当前排序的兼容模型时显式切到结构评分，回到原快照后可恢复原兼容排序及模型。模型和词典不会在按键路径读入。

补充词典的合法来源标识可长于启动基础词典。托管宿主按固定登记资源实测上界预留帧与恢复材料。目前登记词典最多需要每输入字母 6 字节正文及每边 141 字节来源标识，预留分别为 8 和 160。启动词典已有的实际容量继续保留。更大资源仍需经过既有容量预检，宿主全局预算沿用。

宿主将资源配置交给独立后台，并在原组合、确认事务和 Unknown 安全收尾后，对两个核心作一致的配置与容量预检，随后在同一线程发布。发布使旧输入修订、候选、音义和翻译来源失效。某宿主失去资源或预检失败，旧版继续生效；其它宿主各自发布准备成功的版本。有界后台心跳报告期望修订、当前修订、代次、词典及模型身份、用户层代次和失败原因。
