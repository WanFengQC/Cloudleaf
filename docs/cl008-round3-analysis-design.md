## 正确性结论规则

每个配置保留全部案例，重复或缺失 ID 立即拒绝。每条候选按原次序逐 rank 比较 text、整数 score、完整 IDs 路径、全部 features 和 records 来源许可对象；另核对状态、waiting 和原文回退。既有完整对象比较继续保留，新增报告只展开差异，不以只比较文本代替路径正确性。

完整参照要求 Reference 的 status=ok、guaranteed=true、无工作预算、无 Beam 剪枝且整图未截断。候选方法同样完整时才给精确等价布尔结论；Reference 不完整、候选被剪枝/触预算或非法拒绝时，完整正确性结论必须为 null，并列明原因。Reference 不完整但旧 Exact 完整时，可另列 Position 对旧 Exact 的同实现谱系对照，明确不是独立穷举验证。

Beam1 的已有增删、排名和路径变化全部保留。相对于完整 Reference 的可观察候选丢失可以报告，但 Beam 有损时不得标为精确等价通过；两个不完整输出恰好相同也不得成为完整正确性证据。不同预算触发只登记实际观察，不虚构某条路径在某次剪枝丢失的因果日志。

完整参照下精确策略出现差异即保存失败报告并非零退出；发现实际算法缺陷，先补单独设计与最小复现，再修实现及配对重测。没有实质缺陷时不为产生提交改动算法。

## 资源分析规则

每个数据集、配置和 kind/输入字母长度组分别给案例总数、拒绝/空/非空、预算原因、Beam 剪枝、扩展与驻留高水位，以及全部有序样本合并后的 P50/P95/P99/max。另列最大单例分位数，名称与混合样本分位数分开；拒绝和预算案例保留并单列，不能以快速失败冒充完成搜索的速度。

内存为每配置独立进程峰值，不能派生成每例内存。记录载入时间、词条与 Trie 数、计时数组等总峰值范围，路径驻留计数与字节峰值分开。每例对照图边/扩展/驻留/预算及候选完整性；耗时包含规范化、建图和搜索，目前没有阶段计时，因此不假称知道各阶段耗时占比。

固定分析历史 `unihan-after.json` 中 Position 标准配置的 13 个 P95>5ms 案例，以及全部 short/Unicode 和边界案例。新一轮仍列出该固定队列，无论新测量是否回到阈值以下；同时另外列出新超限集合。按输入长度、图边、扩展、驻留与同图旧 Exact 对照解释机制工作量，比较短例比率；后台负载未隔离、样本有限，比例不是显著性或最优证明，不据此调参数。
