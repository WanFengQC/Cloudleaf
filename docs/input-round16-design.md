# Round 16：按完整正文评分的字符上下文模型

## 问题与边界

Round15的Structural每词-100，Lexical仅在结构同分时比较一元观测，因此“我/爱昵”的-200始终高于“我/爱/你”的-300。旧完整格中存在目标正文；增大一元计数不能改变该比较关系。保留全部旧评分及回归，新模式显式启用，默认构造不变。

本轮先实现一种有明确概率意义、与词典分词边界无关的字符Bigram，而不同时堆叠未经校准的联合权重。词级Bigram继续作为旧对照，其单位是词典ID，不能将字符语料的计数直接当作词转移。

## 数学与格式

新`Ranker::CharacterBigram`仅比较完整正文的字符语言分。Unicode scalar为语言单位，BOS/EOS各出现一次，未知scalar映射到单独UNK。训练计数为真实序列中相邻字符及边界的次数。

令V为已观测字符与EOS、UNK的集合，使用既有add-one平滑：`P(y|x)=(C(x,y)+1)/(C(x)+|V|)`。固定分为`log2_fixed(C(x,y)+1)-log2_fixed(C(x)+|V|)`，单位1024；完整分是BOS到所有正文字符再到EOS的和。同正文不同词典切分得到完全相同的分数。语言分不混加每词-100、人工词频、一元词汇和或前缀惩罚；这些仍由Features诊断。完整概率仍有文本长度与语料领域偏差，不能声称消除了全部自然语言偏差。

兼容扩展既有`cloudleaf-language-v1`，增加`kind=character_bigram`，字符token是单个非空白Unicode scalar；BOS/EOS保留现有拼写。词典SHA、来源SHA、许可、usage和train划分保持强绑定。保留原bigram/lexical reader、训练器及旧模型字节语义。格式入口继续有16MiB、200000行、100000句、1000000token/1100000转移上限，计数平衡及BOS/EOS连通性校验。只接受mechanical/research_only。

复用BigramModel与LanguageSnapshot外部接口；字符模型载入后使用数字字符键、预计算固定分及每词条内部字符分，热路径只查边界转移，无String分配、对数计算或磁盘访问。缓存由固定词典和模型共同生成并计入模型容量；不建立Unicode平方稠密表，不提高Windows Host资源门槛。

独立审查实际复现了低层API将缓存用于另一词典时的错误评分和越界panic。预编译缓存因此另外绑定不可变Lexicon实例标识：move和Clone保留标识，新载入实例必须重新在该实例上载入模型。公开search入口一次检查缓存身份，Input配置入口同时拒绝不匹配，不在逐边评分中重复校验；原有词典文件SHA绑定继续独立有效。

## 搜索状态与完整性

Reference逐路径完整枚举后比较；ExactDag/Beam新模式的充分状态为`(拼音位置, 最后一个模型字符)`。词内部转移可缓存，跨词边界使用该历史字符，结束加EOS一次。相同正文必有相同最后字符，状态内去重保留语言分最高、稳定词条ID顺序最前的路径。PositionDag保持原无历史语义，拒绝新评分，不能以位置桶错误合并历史。Beam保留剪枝计数，不宣称精确；任一图/扩展/驻留预算失败保持非完备，输入层不发布不完整候选。

分数是有限负整数，最多受已校验词条正文长度和输入边数控制；新增诊断为字符语言分、字符数、UNK数及结构分。历史Features字段含义不变。完整查询对同一模型/输入/配置确定性。

首轮真实171事件中字符前向Exact达到P95 20.5748ms，复杂句耗尽200000扩展；因此字符Exact改为同一充分状态的反向DAG最优后缀分，再以该精确上界优先枚举完整路径。后缀每个状态/边评分和前向每次边扩展都消耗同一expansion预算，后缀标签与待处理路径也计入resident预算；不提高门槛。已取得K条不同正文后，仅当剩余上界严格低于第K分时结束；同分必须继续比较稳定ID，不丢弃平局最优路径。Reference保持穷举，Beam保持原前向历史桶用于独立对照。该优化不改变概率、K或词条格，不是用有限旧TopK池重排；预算失败仍非完备且不发布到输入层。
