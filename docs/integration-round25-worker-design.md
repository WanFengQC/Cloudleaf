# Round 25 离线翻译计算资源约定

基线为 `403ace1c9d95993f6117113f94924b58aee998bb`。Round 24 默认词汇模式和研究词语模式的并发 P95 分别为 16.50 和 4.36 ms，空闲为 6.77 和 2.54 ms。上一轮已核对独立进程内有界队列、单任务调度、线程池内实际返回的线程数和冷加载分段。由现有数据无法把总延迟归因于单一资源。

## 增量实现

- `cloudleaf-translation-ipc` 在保留显式 1、2、4 计算线程档的同时提供针对可用逻辑 CPU 数的自动选档，尽量保留两条逻辑处理器的空间。默认最多 2，CPU 数低或探测失败时为 1。现有调用者的显式档行为保持。
- 通过 Windows 上已有 `CommandExt::creation_flags` 增加显式、仅对子进程生效的低于正常优先级选项，正常策略仍为默认。CPU 组亲和性只在无窗口实验保持动态拓扑控制，收集证据后再决定产品级接口。
- `cloudleaf-offline` 引入可跨方向重用的有界 Marian 计算池。Worker 只持有一份池和一个方向的模型。相同方向的后续请求继续复用热模型；方向切换先销毁模型再装载新方向，原取消、版本检查及队列上限保留。
- 加载和推理都在已校验大小的独立池中执行。对照锁定源码中的 Candle CPU GEMM 分派、Rayon 池并行范围以及 Windows 工作线程实际占用。只有存在完成结果且验证了完整任务身份的记录参加统计。

## 无窗口验收

- 复用固定 171 键与两个输入模式。交替运行正常、自动线程和实际可核验的逻辑核心隔离策略。固定正文和模型，分别报告空闲和已确认与真实推理窗口重叠的按键分位数、线程 CPU 和周期、进程内存、线程及 I/O。
- 另以开发短轨迹覆盖长串、连删、编辑、多次提交、同向连续请求、跨方向及取消后的输入。保留每轮命令、原始输出、失败、分母、词典及模型和二进制哈希。
- CPU 计数与墙钟差只作观察，不替代调度等待。进程采样不推断单次内存带宽及分配器内部争用。真实窗口、系统输入法和长测不参与。本轮保持无新权重下载。
