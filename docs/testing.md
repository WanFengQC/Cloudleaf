# 云笺（Cloudleaf）测试与质量保障规范

- 文档路径：`docs/testing.md`
- 文档版本：2.0，2026-10-22
- 目标：保证核心行为正确、输入流畅、翻译故障隔离、平台接入可靠且发布可重复

## 1. 测试原则

1. 先测试平台无关核心，再测试平台适配。
2. 输入正确性和性能必须分别验收。
3. 所有关键行为均应有自动化回归用例。
4. 性能结果必须注明硬件、操作系统、构建模式、数据规模和测试集版本。
5. 翻译服务故障不应导致基础输入测试失败。
6. 测试数据、词典、模型和语料必须有明确来源及授权。
7. 不能以编译成功代替真实输入法集成验证。

## 2. 测试层级

### 2.1 单元测试

验证单个模块的确定性行为，包括：

- 输入状态机转换。
- 拼音分段和非法输入。
- 退格、取消和提交状态。
- 词典查询和多义词匹配。
- 候选生成、去重与排序。
- 配置解析与版本迁移。
- 翻译请求构造和错误映射。
- 缓存命中、失效和清理。
- 任务取消与过期结果过滤。

### 2.2 属性测试与模糊测试

适合验证：

- 任意合法按键序列不会导致崩溃。
- 输入状态转换后内部状态保持一致。
- 候选索引始终在有效范围内。
- 拼音解析对极长或异常输入有明确的资源上限。
- 配置文件和词典文件损坏时能安全报错。
- 翻译服务的异常响应不会导致解析崩溃。

如果引入属性测试或模糊测试依赖，需单独审查其许可证和维护状态。

### 2.3 集成测试

验证模块组合后的行为：

- 输入事件到候选列表。
- 候选选择到最终提交文本。
- 词典查询到候选注释。
- 整句请求到翻译结果。
- API 失败到可配置的回退策略。
- 翻译进程退出后输入仍可工作。
- 配置修改后运行时行为符合预期。

### 2.4 平台兼容性测试

必须在真实目标操作系统和真实应用中验证输入法注册、激活、组合文本、候选窗口、焦点变化和提交行为。

模拟器或核心测试程序无法完全代替系统级测试。

## 3. 输入核心测试集

本节事件语料用于行为回归；独立算法质量集按 [algorithm-evaluation.md](algorithm-evaluation.md) 分train/dev/heldout及意图家族，不能与41条事件回归混为准确率评测。候选Top-1/Top-5/MRR、OOV/无候选总体分母、纠错/上下文与逐例变化分别统计。当前手写种子仅验证工具，正式规模/代表性与主要算法比较未据此完成。

建立版本化的输入测试语料。每条用例至少包含：

- 用例 ID。
- 初始状态。
- 按键事件序列。
- 预期组合文本。
- 预期候选及排序。
- 预期高亮候选。
- 预期提交文本。
- 预期最终状态。

测试分类：

1. 常见单音节和多音节拼音。
2. 连续全拼输入。
3. 不完整音节。
4. 有歧义的分段。
5. 退格到空输入。
6. 快速输入与重复按键。
7. 候选选择和翻页。
8. Space、Enter、Escape。
9. 中英文模式切换。
10. 标点和数字输入。
11. 焦点变化和上下文重置。
12. 无词条、词典缺失和词典损坏。

候选排序规则变化时，应运行完整固定语料并比较候选位置变化。预期变化必须在评审中确认，不允许无解释地接受大范围排序回归。

## 4. 翻译测试集

### 4.1 词典查询

覆盖精确匹配、大小写、词形变化、词性、多义词、短语、未命中、重复词条、无效编码和版本升级。

### 4.2 整句翻译

覆盖中译英、英译中、自动识别、长句、标点、换行、混合语言、专有名词、否定、数字、日期、单位和服务端错误。

### 4.3 提供者行为

- 提供者未安装。
- 模型加载失败。
- 网络不可用。
- API Key 无效。
- 服务端限流。
- 响应格式不正确。
- 响应超出大小上限。
- 请求超时。
- 用户取消。
- 任务返回时原输入已变化。
- 翻译进程崩溃或重启。

所有故障场景都应验证基础输入仍可继续使用。

## 5. 性能测试

### 5.1 指标定义

- **核心处理延迟**：从核心收到统一输入事件到返回候选帧的时间。
- **词典查询延迟**：从发起查询到得到查询结果的时间。
- **端到端延迟**：从系统按键事件被输入法处理到候选窗口完成可见更新的时间。
- **冷启动耗时**：进程启动到核心可处理输入的时间。
- **首次查询耗时**：初始化后首次候选查询的耗时。
- **常驻内存**：稳定输入场景下的进程内存使用。
- **翻译任务延迟**：从发起翻译到结果返回的时间，单独统计，不与核心按键延迟混为一谈。

### 5.2 初始目标

| 指标 | 初始目标 | 说明 |
|---|---:|---|
| 核心输入事件处理 P95 | ≤ 5 ms | 固定基准环境下测量 |
| 核心输入事件处理 P99 | ≤ 10 ms | 不包含 UI 绘制与远端请求 |
| 常规本地候选查询 P95 | ≤ 5 ms | 记录词典规模和候选数量 |
| 网络请求对按键路径的阻塞 | 0 ms 同步等待 | 架构性要求 |
| 模型推理对按键路径的阻塞 | 0 ms 同步等待 | 架构性要求 |
| 过期翻译结果覆盖新结果 | 0 次 | 必须由自动化测试验证 |

以上为初始工程目标，不是当前实测成绩。若在目标硬件上无法达到，必须提供基准数据、瓶颈分析和经评审的调整方案。

### 5.3 基准方法

- 使用固定版本的词典和测试输入序列。
- 在 release 构建中运行主要性能测试。
- 预热后分别记录冷启动和稳定状态。
- 记录 P50、P95、P99、最大值及样本数量。
- 分别测试空闲系统和常见后台负载。
- 记录 CPU、内存、操作系统、Rust 工具链和提交版本。
- 性能测试不得依赖实时网络服务。
- 将核心计算、IPC、平台调用和 UI 更新分开计时。

### 5.4 压力测试

- 长时间连续输入。
- 大词典和大量用户词条。
- 极长输入序列。
- 高频退格和候选翻页。
- 多个翻译任务同时排队。
- 网络服务持续超时。
- 离线模型反复加载和卸载。
- 设置变更与输入同时发生。

检查内存持续增长、队列无界增长、锁竞争、线程泄漏和响应时间尾部恶化。

## 6. Windows 兼容性矩阵

首发版本至少覆盖：

- Windows 10 与 Windows 11 的受支持构建。
- 记事本。
- 浏览器地址栏与网页输入框。
- 常见办公软件中的文本输入。
- 多行编辑器。
- 管理员权限与普通权限应用之间的切换场景。
- 远程桌面或虚拟环境（列为兼容性观察项，是否正式支持另行决定）。

每个目标应用测试：

- 输入法切换。
- 组合文本更新。
- 候选选择。
- 最终提交。
- 退格与取消。
- 焦点变化。
- 多行输入。
- 中文标点。
- 翻译服务异常时继续输入。

必须记录操作系统版本、应用版本、复现步骤和结果。

## 7. 跨平台测试策略

Windows 首发阶段：

- 核心 crate 在 Windows 上完整构建与测试。
- 尽可能在 Linux CI 上构建公共核心，提前发现平台耦合。
- macOS 适配实现后增加 macOS 专属构建和真实输入测试。
- Linux 适配实现后增加目标发行版、Fcitx5/IBus 对应测试。

共享核心的固定测试输入应在各平台得到一致的核心结果。平台 UI 细节允许不同，但文本、候选顺序和翻译语义不能无故不同。

## 8. 自动化质量门禁

每次提交或合并请求至少执行适用的：

- `cargo fmt --check`
- `cargo clippy`（按项目配置设置警告策略）
- `cargo test`
- 许可证与依赖清单检查
- 数据文件格式与校验和检查
- 独立算法数据防泄漏、指标分母与基线/消融报告
- 核心平台宿主契约（身份、重复事件、异步提交三态）模型测试，不替代真实TSF
- 核心基准测试（按变更范围触发）
- 平台构建任务（按代码路径触发）

具体命令应在项目初始化后写入 CI。禁止把未经测试的二进制直接作为正式发布版本。

## 9. 故障注入

至少模拟：

- 词典文件丢失。
- 配置格式损坏。
- 磁盘空间不足。
- 翻译进程被强制结束。
- API 连接超时。
- 无效 JSON 或不符合协议的响应。
- 大于限制的服务端响应。
- 用户取消后任务仍返回。
- 应用失焦时候选窗口仍收到更新。

期望结果是错误被限制在相应模块内，核心输入状态保持一致，用户能够继续输入。
