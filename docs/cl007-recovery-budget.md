# CL-007 模块级恢复预算约定

2026-10-23；先提交本约定，再实现 `adapters/windows/budget.rs` 及平台接入。只限制平台临时恢复资源，不改核心算法或默认词典，不注册、激活或注入真实应用按键。

## 计费对象与取得时机

模块内所有线程、活动 Host、退休资源及尚未放弃的恢复材料共享同一预算。四个独立硬上限为 Host 资源槽、来源 epoch 批次、恢复文本容量、必要固定/动态开销字节；不能用单窗口限制代替模块上限。初始研究上限为64个 Host 槽、64个 epoch 批次、4MiB文本容量及16MiB开销容量，最后须与真实 `size_of`、已载词典和输入边界推导、跨实例压力记录一并报告；这些是本轮保守资源策略，不是正式产品体验指标。

实际尺寸推导后，本轮诊断策略调整为 **64个 Host / 64个 epoch / 64MiB文本 / 128MiB开销**，再执行真实 COM 多实例压力到失败点。原策略只容纳三个完整最坏 epoch；默认并行中旧 watchdog 测试首键被容量门禁拒绝，串行相同断言通过，保留失败日志。调整依据是完整最坏队列、快照与显示副本的模块容量需求，不把测试线程数当产品需求，也不把保守记账额度说成物理工作集测量。当前原型预计固定开销先约束35个 epoch，确切拒绝点由后续压力报告记录；生产词典与真实应用预算仍待独立审查。

`reserve_host(fixed_bytes)` 在创建平台恢复资源之前取得；`reserve_batch(text_capacity, fixed_capacity)` 在当前 epoch 第一条事件取得 ownership 和修改投影引擎之前取得，覆盖该 epoch 最多32条事件、计划帧/字符串容量、恢复材料的 UTF-8/UTF-16 展示及必要临时副本。容量必须从实际已载资源及核心边界推导，不能从第一次短输入猜测后续上界。超出既定资源/配置上界时停止新接管并明确失败，不事后截断已取得材料。

预算模块自动给每个 reservation 加计其自身结构、可能的 Arc 控制块和保守分配元数据；调用方另计 Host/Store/窗口/broker/Vec 容量等生命周期成本，不能二者都遗漏同一对象。计费字节不等于进程工作集，操作系统窗口和分配器开销另测，不据此声称精确物理内存限制。

## 预留、转交与释放

`Reservation` 不可 Clone；需要共同保有时可用 Arc 共享同一 reservation，克隆 Arc 不再次扣费。计划、ledger 与脱离 HWND 的 Store 转交时保留同一预留，避免先释放后重新申请导致已接管材料因预算竞争而丢失。每条真实 Applied 的确认不等于可以清掉同批 Unknown；仅当该批全部已可靠 Applied 且未转为恢复材料，或用户明确放弃该批，才释放最后预留。窗口销毁、服务停用、焦点变化、超时、线程退出、复制成功均不能自动放弃 Unknown。

预留失败不增加序号，不修改投影状态、不吞新事件、不覆盖旧材料。`can_reserve_*` 仅是只读提示，跨线程状态可变化；必须以真正 `reserve_*` 成功作为接管依据。只读预判本身不预留容量。

预算使用四维原子 `fetch_update` 逐维取得并在任一失败时回滚已取得维度；不会等待 Mutex、其他 STA、网络或文件。临时跨维度占用可能保守拒绝新申请，但不能突破任一硬上限。释放只作原子减计并释放自身模块租约。`usage` 是四个计数的诊断采样，不保证四维同时采样，不能用于强行推断可接管状态。

## 接口与验证

平台私有接口为 `reserve_host(fixed_bytes)`、`reserve_batch(text_capacity, fixed_capacity)`、只读对应 `can_reserve_*`、`usage()`、`limits()` 和 `reservation_overhead()`。`Usage` 明确含 `hosts / batches / text_bytes / fixed_bytes`。非法零容量、算术溢出及预算不足均拒绝；无 reset/强制清空生产计数入口，不允许忽略活跃 token 重置获得表面通过。

独立测试使用相同 Pool 实现和独立计数域，覆盖逐维耗尽、失败回滚、溢出、跨线程竞态、Arc 转交/最后释放、拒绝不修改已有预留及反复压力。生产 COM/Win32 测试另外覆盖多个 Host/epoch、活跃与退休材料共同耗尽、输入接管前失败、Applied与Unknown的不同释放路径、外部窗口销毁后重开和最终用户放弃。仅独立计数器测试通过不能声称集成正确或完整A1–A5退出。
