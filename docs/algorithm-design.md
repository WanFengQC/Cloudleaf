# 云笺核心算法设计

- 文档版本：1.0，2026-10-22。
- 对应任务：CL-004；与 CL-005 评估、CL-006 平台契约共同约束后续 CL-008。
- 产品目标：输入准确、完整、流畅、可解释、可持续改进的正式输入法。
- 状态：完成算法分层、备选方案和实验要求的设计；本文中的目标接口、候选图、语言模型、纠错及学习不表示已经实现。

## 1. 现有实现与能力缺口

先保留可重复的 M1/M2 基线，再逐项实验和替换。当前源码具有以下行为：

| 模块 | 已实现 | 未实现及当前限制 |
|---|---|---|
| `cloudleaf-pinyin` | 手写常规音节表、大小写归一、多路径分段、撇号边界、末音节前缀 | 每位置及最终最多32条路径；先完整、少音节、字典序裁剪，不使用词典或语言概率；输入最多64个ASCII字节 |
| `cloudleaf-dictionary` | 整个读音的精确索引、最后音节的前缀索引、严格TSV校验 | 查询要求音节数相同，不返回覆盖输入不同区间的词条边；只有64条手写原型数据 |
| `cloudleaf-candidate` | Exact优先、词频/字数降序、ID升序、按提交文本去重 | 只对整条读音匹配词条；没有整句路径、上下文模型、纠错特征和个性化 |
| `cloudleaf-input` | 同步事件、光标、候选分页、模式、生命周期及提交确认 | 每次编辑重算解析与候选；每页5条、输入帧最多50条；未实现平台宿主或异步候选计算 |

这些数字是原型边界。最终输入长度、页大小、搜索预算和候选数量必须在正式词库与真实平台评测后确定，不能直接沿用为产品能力上限。实现依据分别位于四个 crate 的 `src/lib.rs`；原型记录见 [M1/M2实现约定](m1-m2-design.md)。

## 2. 分层及共享约束

目标处理链为：原始输入与编辑事件 → 规范化及位置映射 → 拼音图 → 词条候选格 → 有界整体搜索 → 可解释排序 → 候选帧。输入状态、提交和取消仍由 input 模块管理，平台层消费结果，不参与搜索或打分。

所有算法遵守以下约束：

1. 同一输入、词典/模型/配置/学习快照和算法版本，输出顺序可重复；并行任务完成顺序不能决定候选次序。
2. 原始输入始终保留。规范化、纠错和搜索失败不覆盖原文，不静默删除非法字符。
3. 只有覆盖输入全部有效区间的路径可以标为完整候选。前缀补全、纠错和原文回退必须有独立类型，不能混报精确命中。
4. 网络、模型载入、磁盘写入、离线翻译和词典导入不进入按键同步路径。轻量排序模型使用已经载入的只读快照；是否允许进入同步路径由基准决定。
5. `text` 与候选注释独立；释义、在线翻译返回与网络状态不参与候选排序，不进入默认提交文本。
6. 任何增量结果都绑定输入上下文及修订号。失焦、编辑、配置/词典切换后的旧结果不再适用。
7. 搜索限额同时约束状态数、边数、候选数和内存；不得只限制最终输出而在内部创建无界候选。

本节是算法约束；平台上下文、事件及提交回执以 [CL-006核心与平台契约](core-platform-contract.md)为准。内部实现可以调整，不把语言模型或数据格式绑定到 Windows UI。

## 3. 数据契约

下列为后续实现的逻辑字段，不是当前 Rust API 的声明。增加实际类型前，应同步公共类型、版本与测试。

| 对象 | 必须表达的信息 |
|---|---|
| 输入快照 | 原文、规范化结果、光标/选区、上下文ID、输入修订、模式、方案与配置版本 |
| 位置映射 | 规范化符号到原文UTF-8区间的映射；平台另管理UTF-16位置；不假设两种索引单位相同 |
| 拼音边 | 原文区间、规范音节、完整/末音节前缀、显式边界、扩展来源、编辑代价 |
| 拼音图 | 有序顶点及边、可接受终点、截断/无解状态、算法版本、资源计数 |
| 词条边 | 覆盖区间、稳定词条及读音ID、提交文本、词频版本、词性/来源、匹配类型及可选LM状态 |
| 候选路径 | 完整覆盖证明、词条边序列、上下文模型状态、特征/总分、纠错说明、稳定路径ID |
| 排序快照 | 词典、模型、权重、用户学习和配置版本；禁止搜索中读到半次更新 |
| 候选结果 | 文本、来源、原文覆盖、类型、稳定ID、可选解释、输入修订、是否触及预算及回退原因 |

原文为不可变输入快照。`ü` 到键盘规范 `v`、大小写或方案展开可能改变字节长度，所以光标和删除不能直接使用规范化字符串的字节索引。最终 Unicode 编辑还需区分码点和字素边界；M2 仅ASCII的实现不能作为此类编辑正确性的证明。

## 4. 拼音图与多路径解析

### 4.1 音节合法性及规范化

为正式音节表建立独立版本、来源/许可审查和覆盖测试。音节、儿化、独立鼻音、方言及外来音的支持范围分别登记，不用“完整”代替范围定义。原型手写表可以作为起点，不能以自测通过证明已穷尽合法音节。

采用前缀索引作为首个待测实现；同时比较当前排序表、Trie和紧凑自动机的查询时间、载入时间与内存。标准拼写、`n/l` 后 `ü`/`v`、`j/q/x` 的规范拼写、大小写和撇号分别有明确规则。直接输入 `ü` 的产品处理和位置映射需要新增测试；当前只接收ASCII全拼。

撇号标记不可跨越的音节边界。只有末区间可以是不完整音节；不能把中间非法片段当成前缀后继续解析。尾部撇号保留为待输入状态，不无故补字。数字、标点和混合文本由输入方案及分段规则协调，声调数字不能在没有明确设置时被当作候选快捷键。

### 4.2 待比较方案

| 方案 | 要验证的收益 | 主要风险 | 必须报告 |
|---|---|---|---|
| 当前有界DP | 可重复、已具备固定回归 | 裁剪不考虑词典/语境，长串可丢失正确路径 | gold分段保留率、裁剪率、长度分组延迟 |
| 保留共享边的拼音DAG + 动态规划 | 多条切分共享前缀/后缀，避免重复持有完整字符串路径 | 图和词条匹配的实现复杂；“保留图”不代表搜索无代价 | 顶点/边数、内存、全覆盖分段召回 |
| DAG上的有界Beam Search | 可按词典及轻量上下文保留多条高分状态 | 有损裁剪；局部分数可能错删最终好路径 | Beam宽度敏感性、gold被剪次数、尾延迟 |

这三项是实验候选，不根据名称预定胜者。短串以尽可能充分的枚举作为对照，长串使用可重复的资源预算。解析器生成多路径及代价，不直接决定最终中文；词典和整体候选搜索使用这些信息联合评估。

### 4.3 评分与截断

合法精确音节、显式边界、末音节前缀、方案展开和拼写修改分别进入结构特征。原型“少音节优先”只作为对照，不能成为未验证的全局语言假设。

优先使用确定性的操作/状态预算。搜索触及预算时返回明确状态与安全回退；不能把随机运行时刻的候选集合当作正常稳定结果。额外的墙钟保护用于防卡死，需要记录其触发率和帧退化行为。对耗尽、无解和数据错误分别报告。

## 5. 词条候选格与整体搜索

### 5.1 建图

词典新增“从输入位置开始，返回可匹配读音及覆盖区间”的查询边界；不让平台读取词库内部索引。一个词条可以对应多个有来源的读音。词条边需要同时兼容多条拼音分段，不先选定唯一音节序列再查词。

单字、多字词、固定短语和用户词条都构成词条边。首个位置连接起点，完整词条路径必须到达有效输入终点；撇号只作为边界约束，不进入提交文本。末音节补全可形成另一类终点，其补全代价单列。

未登录片段使用带原文区间的回退边保留，或返回明确的未知片段状态。它们不能被算作词典召回成功，不能用未经确认的“猜词”覆盖原文。用户确认一部分候选时，输入核心负责剩余组合区间和修订更新；这是待新增的部分提交能力，当前一次性整条提交尚不支持。

### 5.2 全局搜索

先比较以下控制方案：

- 只查询整条词条的历史基线，观察句子覆盖缺口。
- 在词条格上计算全输入覆盖路径的结构性实验对照。若没有转移模型，只能证明建图/覆盖可行，不能把得到的词条串称为成熟整句算法。
- 带转移代价的动态规划与有界k-best搜索；状态包含位置及所需的历史词/LM状态。
- 有界Beam候选搜索，再以独立上下文模型重排有限候选；分别评价首轮召回与重排贡献。

候选必须对完整输入共同打分。例如同一输入的词条划分需要比较“词条本身的概率 + 相邻词转移 + 前文条件 + 匹配/纠错代价 + 长度校准”，不能先分别取各音节最高频字再拼接。没有语言转移或整体比较证据的实现只登记为结构实验。

N-gram状态长度、边界标记、平滑/回退方式、词/字混合粒度及OOV策略均需版本化。原型中的人工词频不能被解释为真实语言概率；若转换为对数特征，需登记转换、量纲和缺失值处理。不得把边数增多或文本更长自动当作更高概率。

## 6. 可解释排序与语言模型

### 6.1 对照和特征

保留历史稳定全序作为对照：匹配类型、词频降序、字数降序、稳定ID。新增可解释加权方案时，记录以下特征及计算公式：

| 特征 | 目的与限制 |
|---|---|
| 拼音/读音匹配 | 区分精确、前缀、方案展开和纠错；不以LM无条件压过合法输入 |
| 原文覆盖 | 区分完整覆盖、等待前缀和未知回退；不能忽略中间字符 |
| 词频 | 使用经过审查的数据版本与量纲；缺失不伪造为已观测频率 |
| 词条转移 | 评价词序及组合，不独立拼接局部第一候选 |
| 左上下文 | 仅用平台允许、用户允许的局部文本；无上下文时明确使用无上下文模型 |
| 用户选择 | 有界本地学习快照；关闭后为零贡献，不影响基础可用性 |
| 纠错代价 | 分别计插入/删除/替换/相邻交换、方案及模糊音，不把所有修改当同等 |
| 结构校准 | 路径/词数和长度校准，避免长候选或多边路径无故占优 |

权重仅在训练/开发集拟合或选择。与N-gram、轻量上下文重排比较时，固定词库和候选预算；若词库、候选器也改变，另开实验并分别归因。

特征使用固定精度或明确量化的分数，定义溢出、非有限值和缺失模型回退。分数平局按稳定词条/路径ID排序。候选文本去重保留最优路径，同时保留其来源与覆盖解释；不能让哈希遍历、线程或词典行顺序决定结果。

### 6.2 效果与成本一并验收

整体Top-1提高却损害低频词、错误纠正或长串稳定性时，不直接放行。分组报告、固定事件回归、输入延迟和内存同为选型依据。复杂模型必须证明超出可解释基线的实际收益；没有收益、来源不明、不能离线运行或超出预算的模型不成为默认算法。

## 7. 输入方案、纠错和混合文本

全拼是独立策略基线。模糊音、简拼、双拼和拼写纠错分别开关、分别版本、分别测试；不能通过扩大一个全局候选集合而悄悄改变既有全拼行为。

纠错只在有界邻域生成带代价的边，保留未改动路径。比较键盘邻近替换、相邻交换及音节约束策略，测量错误样本修复和正确样本误改两个方向。既有合法输入的首选被纠错候选挤掉时，必须可解释并有独立证据。空格、数字、快捷键、英文、URL/路径等混合场景先有产品规则，不用语言模型猜测用户是否想切换模式。

每种双拼方案单独登记键位与歧义规则，避免把其输出直接混入全拼。设置变更取消或重建受影响的组合上下文，并更新算法/配置快照；旧候选不可跨方案提交。

## 8. 个性化与用户词典

学习仅由明确、成功的候选提交触发。取消、失败、结果不明的提交、预览、翻译注释到达不触发学习。记录稳定词条/读音标识、选择计数和必要的局部统计；默认不保存完整输入历史，不把原始上下文写入普通日志。

学习可关闭、可清除，关闭时既不更新也不用于排序。用户词典和学习统计分开管理，删除用户词条后不能被缓存再次带回。文件损坏或版本不兼容时保留基础词库输入能力，并提供可诊断的恢复流程。

快照更新在后台执行，输入路径读不可变快照；明确增量写入、崩溃恢复、大小上限及迁移策略。自适应收益在模拟或经授权的用户序列上评价，不拿通用heldout即时学习以抬高准确率。多义词和同音词的个性化不允许泄漏其他应用的敏感上下文。

## 9. 增量、缓存及预算

先实现可验证的全量计算对照，再比较增量算法。增量结果必须与同版本全量计算等价；只报告加速而不报告候选差异不能验收。

- 尾部插入/退格：从受影响边界重用未失效图和索引匹配；不要假设只重算最后一个字符就足够。
- 中间编辑：从前后可影响的音节/词条跨度重建；无法证明依赖范围时回退全量。
- 缓存键：规范化输入、光标相关编辑状态、上下文及输入修订、词典/方案/模型/权重/学习版本。
- 缓存淘汰：有界容量，取消/失焦不保留敏感应用上下文；配置/数据更换使旧结果失效。
- 预算：输入长度、图边、活跃状态、每状态Beam、候选、上下文长度、单次及缓存内存分别计量；有效限额和触发原因随实验记录。

预算值由短词、长串、歧义与大词库实验冻结。当前64字符/32路径/50候选只作为历史对照。最终超过限制时的行为必须明确且不丢字，不能以无限增加限额解决算法爆炸。

## 10. 实验顺序与完成条件

| 步骤 | 交付 | 选择条件 |
|---|---|---|
| A0 保留历史对照 | 固定源码/词典/41条事件回归/基准与提交记录 | 可重复运行；真实成绩和未验证范围分开 |
| A1 数据与评估 | 独立种子集、划分清单、评测程序和基线报告 | 防泄漏检查、所有目标类别有记录，未覆盖项不伪装通过 |
| A2 解析图与词条格 | 多路径覆盖、预算/裁剪计数、OOV回退 | 分段/候选召回与延迟对照；整句路径覆盖全部输入 |
| A3 排序/LM比较 | 加权、N-gram及上下文重排实验，逐项消融 | 独立集收益、回归/分组/资源门禁同时通过 |
| A4 扩展和学习 | 纠错/输入方案/用户词典与学习快照 | 正确样本误改、方案隔离、成功提交学习与关闭/清除测试 |
| A5 增量及平台集成 | 全量等价报告、真实平台端到端测试 | 无丢字/重复提交、无过期结果、尾延迟和内存达标 |

本轮只运行历史规则与“移除Exact优先”的频率排序消融，不实现或选定上述DAG、词条格、N-gram和上下文重排。独立种子集与实验基础设施不代表算法已成熟。具体状态、实测分母和未完成实验在 [算法评估规范](algorithm-evaluation.md)及生成报告中登记。CL-008 的生产选型必须补齐正式词库、数据授权、独立评估和资源证据。
