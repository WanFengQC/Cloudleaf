# Round 10：真实应用人工执行材料，当前未获准执行

沿用`cl007-round8-application-matrix.tsv`九类应用矩阵；逐case使用`cl007-round10-application-record.json`另存真实记录。当前环境、实际快照恢复、负责人、执行授权及TSF批准均缺，所有case保持not_run，不提供或执行注册命令。

1. 用户准备隔离VM，记录Windows版本/构建/架构、快照ID及原件SHA，实际恢复演练并保存结果。填写新的环境请求及实际材料引用，不把模板当证据。
2. 在实际冻结源码/数据/工具/二进制和配置后取得runner的`--preflight-output`只读身份报告；即使缺批准也只输出身份和拒绝原因，不启动child。用`check_windows_soak_admission.execution_identity_sha256(identity)`核规范摘要，用户核验完整identity后另行出具schema2执行授权原件。
3. 材料、档位与身份缺任一项继续拒绝。旧schema1授权不升级；配置、二进制或实现变化必须重新批准。standalone材料checker不证明本次运行身份，`ready=false`不授权运行。
4. 只有用户明确批准后，另行安排连续8h与24h诊断；各segment独立归档，保留中断、资源与原始逐键分母，不累加中断片段。通过长期门禁也不等于TSF已获准注册。
5. 在可靠性审阅、可逆恢复方案及单独TSF人工批准齐备后，用户另行批准受控注册与测试。当前不执行。记录批准文件、DLL/配置/源码/数据身份及注册前后状态，确保故障时能按实际验证过的恢复方案还原。
6. 逐应用记录名称/版本、权限、窗口与焦点条件，保留输入前文字、实际按键、预期及实际文字、候选与提交结果；覆盖全拼/选词/退格/取消/切焦点/多行及Unknown隔离等已有矩阵步骤，不以模拟宿主替代真实应用。
7. 每例保存可核验的实际事件和截图/录像或人工步骤证据path/SHA。异常时先保全原文和上下文，不自动重放Unknown；恢复过程和失败也归档。自审如实注明，不冒充独立审核。
8. 最终报告区分已执行、失败、未执行、环境/人工阻断。CI或材料哈希一致不代替实际输入、长期资源或人签验收。

本轮只完成工具与材料准备，不执行以上长测、注册、激活、安装、卸载或真实应用操作。
