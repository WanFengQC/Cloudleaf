# 生产语义发布器：待实施设计 v1

状态：**设计供审阅，未实现/未启用**。R7的`cloudleaf-linguistic-sidecar-v1`只证明结构、引用、提供的审核声明与数学一致性；不得将其`verified=true`转换成生产发布许可。本设计不改变已有词条schema2/3、TSV v2、当前发布指针或核心接口。

## 内容与版本边界

拟定新的离线`cloudleaf-semantic-content-v2`和`cloudleaf-language-release-v1`发布信封；现v1材料不能静默升级。以下是拟定文件与必备身份，尚不是已支持的命令或JSON schema实现。

|文件/对象|必备内容与约束|
|---|---|
|lexicon引用|每个语言/目录的词条manifest和事实SHA、ID命名空间、支持的schema；现有中文词条包单独仍可使用|
|语义内容|稳定entry引用、POS/tagset版本、人工义项ID/语言、显式有向关系、短语/组件；原源断言位置和原件SHA不能丢失|
|frequency内容|metric/coverage/值/计数/分母单位、语料版本/时期、token与文档协议、原生定义或母观测；无真实观测不创建伪观测|
|source-review|固定source ID/version/original SHA、许可文本/授权/例外/署名/处理协议审核的实际文件摘要与批准范围；research_only不通过生产门禁|
|content-review|作者、两个独立reviewer、必要独立arbiter的决议和理由，逐项绑定内容、来源/授权及所有影响解释的协议|
|validation/migration|完整条数与失败分母、外键/引用/许可范围、逐版本差异、ID增删合并拆分的人工迁移映射、兼容的reader范围|
|manifest|format/schema、实际资源路径/bytes/SHA、所有词典/内容/来源/协议/审核/迁移摘要、builder源码/工具身份、数据许可与修改/署名文件|
|detached approval/signature|由实际发布权限和信任根认可的签署，签名覆盖manifest完整原字节；算法/工具/密钥管理需另审现有发布流程，当前未提供、未实现|

现v1只有一个`known_entry_ids`集合；若英语目标词头并不在获准目录，不能拿中文entry ID或英文释义字符串假装目标词头。v2拟采用带目录命名空间的entry/sense引用；正式中英对齐须同时交合法目标目录和双方义项。此格式需独立实现与方向接口审阅后才能消费，现有默认引擎没有接入。

原始`raw_senses`数组下标只是源证据位置，不自动成为稳定语义ID。人工确认同一义项才可保留既有ID；拆分/合并/撤销必须有显式迁移和新审核。单向翻译不得生成反向equivalent；反查索引只引用同一关系。POS或短语缺来源时保持缺失，不能用统计分词自动补成语言事实。

## 内容审核绑定与失效

计划复用现有UTF-8、排序键、紧凑JSON、末尾LF的canonical规则。内容摘要覆盖完整记录（不含其review自身）；审核绑定摘要覆盖该内容摘要、目录/来源原件/许可/授权审核摘要及提取/分词/语义/来源家族协议摘要。实际review还须保留相应文件，不能只填64字符字符串。

两位reviewer必须不同且非作者；分歧时由不同于三人的arbiter裁定并保存理由。任一内容、原件、授权范围、协议或迁移映射变化使原审核失效；不能由工具重新计算新摘要后代签。R7 IME的三协议review binding保持原定义，与本设计的语义发布绑定不是同一接口。

SHA只证明固定字节，不证明身份、权利或事实。审批签署与可信发布清单的实际权限由项目负责人落实；仓库中自带的“approved”字段、自签key、固定Git SHA、现有v1 validator或CI通过都不能自行成为新信任根。若根、权限或有效审批缺失，流程止于待审候选，不调用发布写入。此处没有实现签名器或引入密码库。

## 复用现发布/恢复流程

优先复用`pipeline.py`的完整verify→不可变哈希release→持`store_guard/publish_lock`复制→验证目标→`atomic_json(current.json)`模式，以及`checked_pointer`、rollback和`recovery.py`的显式恢复条件；不重写已经验证的锁/PID/路径/恢复机制，也不添加未经证明的跨进程恢复承诺。

但当前`verify_release/checked_pointer`严格只接受已有词条包。未来应先增加经过审阅的versioned bundle verifier和格式分派，再接同样的发布原语；**现实现不能发布此新信封**。使用独立、明确指定的数据bundle store，不重用或迁移当前词条store，除非后续单独批准迁移方案。

一个bundle manifest同时固定词条与语义内容；发布只切换一个已完整校验bundle指针，不能先后切两个独立“词典/语义current”制造混版本。旧版输入核心不认识bundle时继续使用原词条路径，不自动启用语义；新加载器以后在按键路径外验证、预载、原子交换只读快照，当前未实施。

|阶段|允许的动作|失败行为|
|---|---|---|
|取得|固定原件/许可/版本/完整SHA，完成真实授权审查|未知范围保持research_only；不复制入生产release|
|构建候选|真实审核内容与协议冻结后离线构建，新目录、确定顺序和全文件清单|缺内容/外键/范围或未知统计值不合约时停止；保留候选和拒绝原因|
|独立验证|校内容绑定、范围、兼容与清单，另有独立质量验收记录|validator通过只代表其声明范围；不能据此签署或扩大语言质量结论|
|审批/签署|实际发布者检查固定manifest及有效人审，使用已认可的签署流程|无信任根、权限或签署时不发布，不自动补签|
|激活|持原guard，复制不可变bundle、再次verify，再原子替换唯一指针，保留previous|任何失败保留原current；不自动选新版本|
|回滚|明确请求、完整验证previous及兼容后一次换指针|previous损坏或未知时拒绝，保留原current和证据|
|中断恢复|复用已确认退出owner、身份/孤儿/指针核对与显式recover|活owner/PID复用/权限未知不清理；不把进程退出当物理断电验收|

用户词库、学习数据与隐私配置不在发布者的资源清单/目录/复制和清理范围。bundle不写用户目录，不删除旧可用版本，不把语义回滚当用户数据回滚。与新格式相关的用户ID映射或迁移未设计/验证完成时拒绝启用该功能，不能改用户词库来配合测试。

## 实施前交付门禁

1. 实际现代语料/内容授权、作者和两独立review/仲裁及语义内容已交付；禁止以20项待审队列或词典派生gold代替。
2. 发布负责人、可信key/清单和权限材料明确；对清单内容和历史版本承担实际审批，工具不会替代。
3. 新format/manifest/ID引用/迁移经设计审阅，继续兼容原schema2/3词条；其reader/installer/发布器实现有明确范围。
4. 再实施最低必要验证：未审或失效内容拒绝、同固定输入双构建、损坏/混版本拒绝、真实临时目录激活/回滚/中断、旧词条及用户数据保护。已有回归全部保留；不是为加测试数量重演无变化的旧压力。
5. 独立质量、分发许可、正式数据和平台各自退出条件满足前仍不进入CL-010；物理断电、签名部署和真实应用要另取实测证据。
