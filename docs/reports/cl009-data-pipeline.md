## 重复构建与检查

最终实现的三个 Python 模块摘要写入每个 manifest；测量程序同时记录构建时与当前模块指纹，二者一致。最终源码两次从同一锁和原件纯离线构建，全部 9 个文件逐字节一致，manifest SHA-256 为 `e8e0074d3f3035d057db4e47dea154707a5e518bdfb328bb32f6134eea5468da`。两次构建约 7.652 / 10.888 秒，进程峰值工作集约 353.5 / 352.2 MB；第二次与工程检查并行，桌面后台负载未隔离，不能据此确定产品预算。

执行命令及退出码见 [检查记录](cl009/validation.json)。Rust build、fmt、Clippy `-D warnings`、60 项 Rust 测试、doc-test、32 项 Python 测试（其中管线 18 项）以及 4 项资源审计通过。所有原有测试保留。首次终端缺 Cargo PATH，补 README 的进程级 PATH 后完整重跑通过；这不是源码失败。还从 Git 索引按 Windows 自动换行设置导出干净副本，官方许可及 JSONL 校验值保持一致。

可从仓库根按 [操作说明](../../tools/data_pipeline/README.md) 重放。构建只读取本地原件，单元测试将网络调用替换为立即失败以验证离线约束。数据测试覆盖来源/许可锁、归档越界/体积/UTF-8、缺失值、冲突、确定性、音节表与 Rust 一致性、重算哈希后的恶意事实/投影/索引、符号链接、版本指针和并发写者。

## 发布与失败路径

对真实规模的旧本地构建包与最终包执行激活、升级、回退、重新激活和同版本幂等检查。两个包来自相同 Unicode 原件，仅构建清单不同；这验证发布机制，不能称为跨正式数据版本升级验收。最终包具有当前源码指纹，旧包是本轮早期本地构建，不是已发布产品版本。

在专用 `.local/cl009-real-validation` 存储中，损坏待激活资源、模拟 `os.replace` 失败、已有写者锁和损坏回退目标均被拒绝，`current.json` 原字节保持不变；独立用户词典文件哈希不变。完整状态指针与失败原因见 [真实重放证据](cl009/real-acceptance.json)。可重放的相同失败场景同时在 `tests/test_data_pipeline.py` 中运行。正式安装器签名、进程崩溃锁恢复、断电持久性和用户词典迁移尚未交付。
