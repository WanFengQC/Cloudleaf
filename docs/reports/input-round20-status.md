## 代码与正确性

- `cloudleaf-search/src/search.rs` 在字符精确搜索中复用已经求出的后缀，为有效首边构造真实完整候选。只有已经得到 K 个不同正文，才用完整成本、偏好、分数、词条与边来源顺序建立剪枝门槛。比较门槛时借用现有路径，减少反复复制排序键。Reference、默认旧字符路径和原 200000 展开、50000 驻留预算保持原约定。
- 原热点观测发现，`n×32` 失败处有约 2,593 个后缀标签、23,743 个已见前缀、23,659 个排队前缀，已物化 29,857 个路径。种子每次遍历都计入展开并检查取消，驻留仍计标签、候选与临时路径。预算失败保留预算类型和原文，取消丢弃尚未发布的候选。
- `cloudleaf-search/src/transition_cache.rs`、`schemes.rs` 与 `cloudleaf-input` 提供有界的 Trie 音节转移复用。缓存键由词典身份、起点节点与规范音节组成，存储命中与未命中，最多 4,096 槽。每键仍构建当前完整图并计算候选。追加、退格、中间修改与光标操作可复用同一词典的转移。会话清空、方案及词典切换使缓存失效，资源/模型/配置替换重建后端。候选 revision 和事务仍以当前输入为准。
- 输入引擎的缓存默认关闭。实测比较得到的理由见下文。显式启用路径无 I/O，默认全拼不分配槽。Windows Host 将两个槽表最大容量计入原 128 MiB 内部账本。该账本与采样的整进程工作集含义不同。
- `incumbent_resources.rs` 的机械反例原先在 256 驻留预算失败。优化后两个字符模型都用同一预算得到完整候选并与 Reference 比对。缓存开关回归逐项比较帧、诊断、Features、来源、判定与旧候选拒绝。无窗口事务回归覆盖已确认提交的学习凭据、NotApplied 重试身份、Unknown 隔离、队列满拒绝、异常导入后的旧代和退出释放写锁。

本轮仍为同步输入。Cancellable 格与搜索 API 有检查点，为新种子保留了取消检查。方案解释和同步 Windows 按键处理尚无后台抢占，超时、主动取消和确定性预算失败没有合并成同一结果。旧结果隔离继续依赖当前 revision、会话、候选身份和已绑定资源的预检。

## 整合与放行

PR #1 是输入检查点的祖先，#2–#5 各自分叉。只读预览在四条方向分别发现 9、3、11、5 个冲突路径。搜索与 Windows 已有部分代码按路径导入，词典发布与翻译仍各有独立能力。将来应在获批的隔离整合分支逐项合并接口、审计和 CI 目标，保全本地双向翻译推理、离线权重的来源边界、用户词库和输入事务。见[整合准备报告](cloudleaf-integration-readiness.md)。

真实 Windows 隔离窗口验收记录为 `not-run/user-paused`。[人工验收清单](../testing/round20-windows-manual-acceptance.md)覆盖添加、上屏、学习、重启、恢复与故障确认。无窗口测试、适配层单测和 CI 只证明各自覆盖的范围。真实 TSF、长测、正式语言质量、授权数据发布仍待各自门禁，Top-1、Top-5、MRR 保持 `null`。

整体为 **partial**。Round 21 优先复测简拼 Lexical 和两字符模型的长尾瓶颈，尤其是格交集与大量同音候选的分配成本。真实窗口按已暂停的验收记录管理，分支整合按独立审阅安排。`main` 与五个 Draft 的验证记录在回执中，CL-010 保持关闭。
