# Round 24 逐例候选丢失诊断

历史分母是 Round 23 的固定 40 条来源正文。对原本有基础词典全拼的 25 条，补充词典冻结包中的按键完全相同。对其余 15 条，独立的补充词典冻结包提供诊断用全拼，基础组仍保留原始不可映射记录。这些按键来自词典派生，缺少人工输入意图。

图可达与其它栏目是不同阶段的证据，各行的原因栏目合计 40。已有 Round 23 对应池的候选数、正文是否进入、预算、完成态和三种同池重排名次均逐例重合。补充结构池在 Round 24 新测。

15 条词面缺失在忽略读音、任意词条组合下仍无法覆盖全文，共有 39 个位置对应的单字词面未收录。两套资源的 40 条诊断按键均有完整合法的全拼音节序列。基础词典 25 条、补充词典 40 条支持与目标词条边界一致的全音节路径。两套词典的目标格分别存在 25、40 条可达正文，其中 25、39 条正文可由多个格路径生成。诊断记录每个正文的路径数、一个可达路径的词条 ID 以及真实召回代表路径。去重代表选择、错误状态合并和错误剪枝对个案的影响均为 unknown。7 次未收录且驻留预算终止的搜索若增加预算，能否进入 Top-50 仍待证明。

完整池内排序退化以同一集合的有限字符重排为对照。两者共用种子池及实际保留的路径代表。正文名次及各评分构成均有记录。`PoolRecallLoss` 说明正文格可达且完整 Top-50 未包含该正文。词面有覆盖却缺匹配读音、全音节分隔、图截断和无法定位均有独立标签，历史样本在这些阶段没有额外归因。

从工作区根目录构建并重放。

```powershell
$env:CARGO_TARGET_DIR = ".local/target"
cargo build -p cloudleaf-input --example recall_diagnose --release --locked --offline
python tools/performance/round24_recall_diagnosis.py --binary .local/target/release/examples/recall_diagnose.exe --output .local/round24-recall-diagnosis
```
