# M1/M2 实现约定（2026-10-22）

本文补充已有架构与输入行为规范，先确定公共接口和原型行为，再接入实现。范围为工程初始化和平台无关核心；Windows TSF、安装包、真实应用验收属于 M3。

## 工程边界

- Rust 固定为已发布稳定版本 1.90.0，MSRV 同为 1.90.0，edition 2024，resolver 3；升级须同时修改工具链、workspace 和 CI。
- `cloudleaf-types` 仅放公共事件、候选、错误及提交协议；拼音、词典、候选与输入分别建 crate。`cloudleaf-cli` 是测试宿主和基准入口。
- 所有核心 crate 不访问网络、文件系统或平台 API；词典从已载入的 UTF-8 文本建立内存索引，加载失败由宿主明确提示并使用空词典演示回退。
- 当前第三方 Rust 依赖为零，MIT 许可；仅用手写原型词条和回归语料。生产词库在 M4 独立审查。
- M1 不引入设置 GUI 运行时：M2 仅 CLI，M3 候选窗口采用 Windows 原生窗口薄适配；设置中心暂定原生系统控件，实际实现前验证无障碍、打包和跨平台成本，必要变更登记 ADR。

## 事件与提交

`InputEvent` 区分生命周期、模式、按键、提交成功/失败确认和显式重试。`InputFrame` 包含状态、模式、原始预编辑、光标、输入修订号、候选集合、高亮与页信息。`Candidate` 的 text 与 annotation 独立。

`CommitRequest` 有唯一递增 ID。核心请求提交后进入 `Committing`；宿主必须先同步执行并回报对应成功/失败，再派发下一按键。成功清空组合；失败恢复组合并保留失败请求，只有 `RetryCommit` 才能以新 ID 重试。失败未处理期间拒绝后续输入，原始事件由宿主保留；Escape 或生命周期取消允许放弃。迟到确认返回 `StaleCommit`，不改变新状态。平台不得把失败确认当成自动重试许可。

没有错误且 `handled=false` 的按键交回系统；有错误时，宿主先处理错误并保留未处理事件，不能直接吞掉。重复确认不重复输出文本。`Cancelling` 是原子清理操作，不作为持久外部帧。

## M2 原型行为

- 初始 `Inactive`，激活后 `Idle`；失焦取消组合并保留激活状态，停用清空并进入 `Inactive`。模式切换取消未确认组合。
- 原文保留大小写；解析归一为小写，`v` 表示 ü，ASCII `'` 强制音节边界。不支持声调数字、模糊音、简拼或自动纠错。最多 64 个 ASCII 字符、32 条分段，候选最多 50 条。
- 完整分段和末音节前缀均可查询，精确匹配优先。尾部 `'` 保留输入但暂不显示新词候选。无效拼音保留原文、候选为空。
- Left/Right 移动原始拼音光标，Backspace 删除光标前字符，插入发生在光标处。到边界不改变文本；空组合 Backspace 交回系统。
- 默认每页 5 个候选，Up/Down 夹取到有效范围，翻页后高亮保持有效。`1..9` 仅选择当前页已有的候选。
- Space/Enter 有候选时提交高亮词条，无候选时提交原文；被消费的按键不额外产生空格或换行。这是 M2 宿主规则，M3 仍需真实文本框验证后冻结系统行为。
- `0` 和超出当前页的数字按普通字符处理，组合中以“原文+数字”请求提交，空闲交回系统。中文模式的 `, . ? ! : ;` 映射为 `，。？！：；`，组合中可提交高亮词条+标点；其他普通字符请求提交原文+字符，避免丢字。英文模式透传按键。
- 提交只含候选 text，绝不拼接 annotation；标点属于明确键入的文本。M2 不学习、不持久化输入、不异步补注释。

## 拼音、词典与排序

拼音解析器手写通用合法音节组合，采用有界动态规划；完整路径优先，较少音节优先，然后按音节字典序取前 32 条。该上限可能截断很长的高度歧义输入，属于原型限制，不能声称完整覆盖所有中文句子。

词典 TSV 带版本头及固定字段，详情见 `data/README.md`。精确查询要求音节数相同，前缀查询只允许最后一个音节不完整；M2 使用词条候选，不拼接多个独立词条组成整句。未知词回退原文。

候选总顺序为：Exact 先于 Prefix、frequency 降序、text Unicode 字符数降序、stable ID 字典序升序；同一文本保留排序最优来源。全为整数与稳定字符串比较，不使用时间、浮点随机数或网络结果。前缀索引的桶预排序、文本去重，每条解析仅取有界前列，再全局排序去重。输入帧最多 50 条候选，候选库公开接口硬上限为 128。排序回归必须记录实际词序。

## 错误和日志

`CoreError` 由稳定 `ErrorCode`、固定说明和可选数据行号组成；错误不包含原始输入、词条内容、凭据或文件内容。核心不直接写日志。产品宿主默认只记录错误码、模块、修订/请求 ID、耗时和数据版本，不记录预编辑、候选、提交文本或完整输入历史。CLI 仅因用户显式运行测试而在终端显示输入与候选，不保存日志。

## 验收与报告

M1 验收包括固定工具链构建、fmt、clippy、test、依赖/许可证/数据校验及 Windows/Linux CI 配置。远程 CI 只有实际运行才可登记通过，本地验证不得冒充远程结果。

M2 验收包括固定事件语料、候选排序回归、提交确认/失败/重复确认、异常输入、有界压力用例及 release 实测。性能报告区分冷启动、核心事件、词典查询和进程峰值内存，记录 CPU/内存/OS/工具链/语料和源码版本；小原型词库达标不能推断生产词库性能或端到端 UI 延迟。
