# Round 28 输入设置热应用设计

隔离 Win32 宿主和设置中心通过同一个配置目录交换状态。设置中心沿用 `InputPreferencesRepository` 的版本检查与原子替换。每个宿主在后台读取已校验的主文件，在窗口线程只轮询有界内存槽。配置文件保存成功表示持久化完成，宿主使用自己的回执报告实际生效版本。启动读取可沿用历史备份；运行中的主文件缺失、损坏或降级保留最近生效配置。

在空组合、无未决及失败提交时，把分页、候选上限、方案、模糊规则、纠错和混排一次应用到双引擎。双引擎都预检成功后执行一次无磁盘操作的内存更新。候选容量按公开上限预留，实际搜索使用用户选择的上限；模型、词典、已提交文档、学习记录与资源快照保持原身份。保留空闲/停用状态，推进输入 revision，使旧翻译来源和候选身份过期。非空组合、失败事务及 Unknown 保留原组合、游标和上下文，等待用户正常收尾或显式重建会话。不重放 Unknown。预检失败时，保留两份当前配置。

后台线程定期更新每宿主的无内容回执。回执包括宿主身份、生效代次、实际配置修订、待处理修订、状态和原因。设置中心只把有效期内的回执显示为在线，不用旧回执推断当前状态。每宿主只保留最新通知与回执，宿主生命周期内的新保存可以替代未生效的旧保存。审核范围为隔离普通窗口；系统 TSF 的注册、激活和真实应用验收保留独立门禁。

改动涉及 `apps/cloudleaf-settings` 的后台传输、隔离输入窗口和加载器、输入核心的双阶段设置接口，以及设置中心的回执展示。验收覆盖跨进程提交、非法与降级文件、活动组合/不确定提交下的延迟、双引擎一致性、分页和候选实际限额、旧翻译来源隔离以及原资源身份保留。
