# 云笺 Cloudleaf 完整产品开发路线图

- 文档版本：2.0，2026-10-22。
- 最终目标：构建算法完善、功能完整、响应流畅、翻译可靠、可长期维护的正式跨平台输入法。
- 当前进度：M1/M2 原型已固定；CL-007/008/009 在独立草稿分支实施，尚未合入 main。owner退出与材料恢复、独立评估门禁、完整授权词条及升级恢复的实际证据和剩余阻塞见[第四轮审阅检查点](reports/cl007-009-round4-status.md)；[第三轮历史](reports/cl007-009-round3-status.md)保留。正式算法、语言质量、Windows验收与翻译仍需建设，不进入CL-010。
- 最终能力由 [product-scope.md](product-scope.md) 的稳定需求 ID 管理。阶段只控制依赖、风险和质量，不缩减最终产品范围。

## 1. 开发原则

1. 保留可测试、可比较、可回退的成果。技术原型证明风险可控，不作为最终功能上限；编译、演示、测试数量或微基准均不单独构成产品验收。
2. Windows、核心算法、正式数据先约定接口再并行推进，最终全链路集成。TSF先接通不代表原型排序被永久固化。
3. 拼音、候选、排序、学习、词典与翻译业务由共享Rust核心独立实现；平台负责系统事件、组合、提交、生命周期与呈现。
4. 基础输入完全本地。网络、数据导入、模型加载和整句翻译隔离在实时路径之外，翻译失败不阻断输入。
5. 隐私默认保护：在线关闭、发送需授权、凭据安全、学习可关闭/清除，不记录完整输入历史。
6. 代码、词典、频率/语言模型语料、评估集、翻译模型及素材分别审查来源、版本、许可和分发权限。
7. 每项完成均须有设计、实现/数据版本、自动化结果、相应真实环境证据、性能/资源记录与未完成边界。

## 4. S0：版本与真实CI

审查实际源文件、测试、报告与许可，显式暂存，排除临时产物、个人配置和密钥；复跑fmt、Clippy、单元/集成/doc-test、release、资源/依赖审计与基准，再固定M1/M2检查点。连接用户指定的 `https://github.com/WanFengQC/Cloudleaf.git`，先检查远程状态，再推送并核实两个平台job、日志和产物上传。

保存提交、源码/二进制/资源校验、命令和环境。报告不能引用包含自身的提交时，用外部检查点和内容指纹追溯，不伪造HEAD。后续每次算法、词库、模型或配置变更都做配对比较，回退不强推覆盖用户历史。

## 5. S1/B：完整算法与评估

详细规则见[算法设计](algorithm-design.md)和[评估规范](algorithm-evaluation.md)。

- 审核音节合法性、`ü/v`、撇号、大小写和混合输入的位置映射。对比当前DP、共享边DAG与有界Beam；保留合理歧义，记录正确路径被剪次数与预算触发。
- 建立覆盖完整输入区间的词条候选格，支持单字、多字词、短语、多种分段、前缀与未知片段。整句经整体路径、词语转移与上下文评分生成；独立词条随意拼接不能冒充整句理解。
- 先建立可解释加权基线，再比较N-gram、上下文重排等方案；报告无收益、失败与退化，不预设复杂模型更好。特征包括匹配、覆盖、频率、转移、上下文、学习与纠错代价。
- 纠错、模糊音、简拼、双拼独立配置/验收，关闭时保持全拼结果。纠错需置信/代价策略和正确输入误改评估。
- 本地学习只保存必要统计，关闭/清除真实生效，敏感上下文不学习；用户词典可管理/迁移，成功确认后才更新统计。
- 增量/缓存与全量参考实现差分对照，输入/词典/模型/学习/配置版本变化时正确失效，速度优化不能掩盖质量下降。

41条事件保留为回归。另建train/dev/heldout隔离数据，按意图/来源家族划分，阻止正确/错误/前缀变体跨split泄漏。当前手写种子集只验证工具和发现缺口，不是盲测或正式代表性语言评测。

报告Top-1、Top-5、MRR、每例排名变化、分段/候选/词典覆盖、IV/OOV、纠错precision/recall、正确输入误改率和分层延迟。无候选、超限、词典外和未支持能力不能从总体分母删除；无纠错预测时precision为null并标明未实现。参数只用train/dev确定；正式质量目标、样本量和统计方法在看heldout前登记。

种子消融只检验局部规则。正式集覆盖不足、阈值未冻结或DAG/整体搜索/LM等主要方案无实验依据时，不能把“设计/工具完成”标作生产算法选型完成。

## 6. A：完整Windows系统适配

详见[Windows设计](windows-tsf-design.md)及[核心与平台契约](core-platform-contract.md)。先审核Rust绑定、许可和必要COM接口；只有明确接口/可靠性问题才评审薄C++桥接，业务留在共享核心。

1. 激活/停用、document/context焦点、快捷键/修饰键、布局/Caps Lock、按键预判与执行、合法连发与重复回调。
2. 原生组合range、显示属性、光标/选区、同步/异步edit session、上下文/修订身份和重入。提交区分Applied/NotApplied/Unknown，未知结果不盲目重试。
3. 候选高亮、数字/鼠标/翻页、系统代绘/自绘、位置跟随、长释义、DPI/多屏、可访问性和窗口生命周期；平台不重新排序。
4. COM引用与sink配对释放、上下文隔离、有界事件队列及溢出恢复；不能通过吞掉所有按键获得表面可用。
5. 服务/profile注册、架构支持、权限、安装升级、回滚卸载和用户数据处理。

真实应用覆盖记事本、浏览器地址栏/文本框、办公软件、多行编辑器、管理员/普通应用切换，远程环境作为观察项。记录系统/应用版本、复现步骤、按键到候选/提交时间、异常轨迹。契约模型不是真实TSF完成证据。

## 7. C：正式词典与数据管线

- 分别选择并审查中文词条/读音、频率/转移语料、双语多义/词性/短语、评估语料及未来模型，不把可下载视为可分发许可。
- Python离线导入、清洗、规范化、去重、校验和构建；不静默补数据/改频率，坏行、来源冲突和质量差异有明确报告。
- 正式格式含稳定词条/读音ID、义项/词性/搭配、来源/授权；数据和索引独立版本。
- 真实规模比较索引载入、查询、磁盘/内存；核心只消费已校验载入的快照。
- 清单/哈希、复现构建、原子升级、兼容迁移、损坏回退和用户词典保护齐全。

64条原型始终保留为基线；英文annotation不是双语词典已交付。无合法正式数据时可登记合成规模测试，但不得报告其语言准确率或冒充正式词库。

## 9. S4：质量、发布与多平台

分开测量解析/搜索/排序、词库载入/查询、TSF/组合、候选显示、提交、学习与翻译。记录冷/热、P50/P95/P99/max、样本数、背景负载、硬件/数据/构建指纹和资源采集方法。

核心初始预算P95≤5ms/P99≤10ms、查询P95≤5ms继续作为工程目标；平台端到端和生产规模资源预算在首轮真实测量后独立冻结。原型性能不等于这些目标已全面验收。

长期压力覆盖大词库、用户数据增长、长串/歧义、中间编辑/连续退格、取消失焦、候选翻页、翻译积压/服务崩溃与资源反复载入，检查内存/句柄/线程/队列和丢字/重复次数。设置、迁移、安装更新/回滚卸载、签名校验、变更说明、许可隐私和崩溃恢复均属于正式发布。

macOS实现InputMethodKit；Linux优先Fcitx5并评估IBus需求。各平台共享算法语料，仅适配系统边界；独立真实应用、性能和安装维护验收不可由核心CI替代。
