# Round 28 混排识别与回放设计

混排继续仅在开启时生效。Round 27 的真实词库回放保留了 `meeting` 的完整原文，但其右侧拼音的同音项改变了整句排名。`check` 则被切成中文 `che` 和字面 `ckyi`，使用户想保留的英文与右侧拼音同时受损。分别记录英文边界、中文候选排名和最终上屏结果可以识别这两类故障。

- 小写英文的证据来自字形和完整中文词条覆盖。保留已有的元音组合与 `-ing` 证据，增加元音后接典型英文辅音韵尾的通用规则。如下一段有输入，则新规则需要长度足够、可完整覆盖的中文右锚点。如左侧有输入，则该位置必须能由当前规划中的完整中文段到达。原文或可疑片段具有完整拼音词条覆盖时，新规则不加分。
- 驼峰拼写内的短区间容易被误当作拼音。当可疑区间位于独立大写首字母之后且在下一处大小写或数字边界结束时，仍要求与普通小写拼音相同的最小长度。连续大写缩写仍可紧邻短拼音。仅在后方有完整中文词条锚点时，以末尾元音组合或形如元音加辅音加 e 的字形保护首字母大写的英文。最后一处大写字母属于缩写时不使用这种加权。
- 仅调整字面段与中文段的边界选择。中文段内继续使用相同词典、同音排序和搜索预算。混排有歧义时继续提供整段原文选项。已有英文原文的大小写、数字、URL、邮箱和代码都沿用原有保护。
- 工程回放保留 Round 27 的 16 条记录，从 Git 外冻结文件读取扩展的原创轨迹。统计位次、全原文可用性、中文学习证据、字面区间、修订冲突、确认与失败后的缓冲保全。分别观察事件延迟、失败分母和实际输出，不把手写输入及参考文本作为独立 gold。
- 先记录旧实现对真正的词典和语言模型的表现，再运行相同资产和事件序列对照。结果保持在本机 Git 外的 `round21-runs`。测试覆盖有冲突的拼音路径，并验证文档中的英文规则对其他词形同样生效。

实现集中在 `crates/cloudleaf-input/src/mixed.rs`，放行条件由 `tests/mixed_input.rs` 的事务及边界回归和 `examples/mixed_input_trace.rs` 的固定轨迹验证。
