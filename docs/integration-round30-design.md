# Round 30 简拼成本与并发验证设计

工作分支为 `codex/integration-round21`。比较基线为 `8c92ea0be4882d69dda97c3642d81b312ef811a7`，该版本的生产实现为 `983a9be991b5e1de2a8d87d12fde8c98f5884538`。

## 候选图和搜索

- 使用归档基线重建普通 Release、计时和分配探针。同机串行执行相同词典、lexical 信号、冻结 171/243 键轨迹及候选、图和搜索预算。
- 独立比较紧凑逆向表、生成时递推和按终点分层的方案。用小型图和词典穷举完整路径与部分路径，核查图边身份、读音边界、输入代价、分数、稳定平局、候选身份及提交文本。
- 保留生成时获知的后缀与预算后的实际边集之间的区别。预算淘汰可以令此前发现的后缀不可用。比较方案必须保留先前的边预算准入次序和部分候选。
- 优先在 `crates/cloudleaf-search/src/schemes.rs` 检查重复 Trie 查询、反向状态和分配。独立比较 `search.rs` 的 PositionDag 拒收路径是否能省掉评分特征的提前物化，保持分数和稳定次序。
- 保持 16,384 条边、200,000 次展开及 50,000 条驻留路径。验证历史 52 个触顶、43 个恢复图、349 个未触顶对照以及事件 78、79 的实际候选帧与后者的 Applied。截断信息和部分结果仍随结果返回。
- 普通 Release 延迟单列。插桩阶段有嵌套，用来解释 243 键长尾，按键信息与预算、分配采样按事件关联。

## Worker

- 复用 `tools/performance/round26_worker_isolation.py` 和 `tools/performance/round29_worker_pairs.py`。为当前 171 键场景提供固定随机种子，生成六轮空闲优先及六轮推理优先的次序，并在运行前记录。
- 两组沿用同一窗口定义、候选和模型身份与相同样本数。汇总倍率仍是合并推理样本的 P95 除以合并空闲样本的 P95。附单轮倍率和两组汇总，保留失败、队列和宿主及 Worker 采样。
- 真实配对、插桩重放、Rust 构建及回归分时运行。任何 CPU 竞争结论须对应观察到的过程或采样。
