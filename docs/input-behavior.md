# 云笺（Cloudleaf）输入行为规范

- 文档路径：`docs/input-behavior.md`
- 文档版本：1.0
- 适用范围：输入状态、拼音解析、候选生成、候选排序、按键处理、上屏与学习
- 首期目标：Windows 全拼输入 MVP

## 1. 目标与术语

本文件规定用户输入时应观察到的行为，作为核心实现和平台适配的共同验收依据。

- **原始输入**：用户键入的字母序列，例如 `zhongguo`。
- **组合文本 / 预编辑文本**：输入法尚未最终提交给应用的内容。
- **候选项**：由核心生成、可由用户选择上屏的文本。
- **候选注释**：候选旁的翻译、词性或简短提示，不属于上屏文本。
- **提交文本**：用户确认后发送到目标应用的最终内容。
- **输入上下文**：当前焦点、组合文本、候选列表、输入模式和必要的局部上下文。

候选注释与提交文本必须分离。用户选择“参考”时，默认上屏“参考”，而不是上屏“参考 reference”。

## 2. 首期行为范围

第一版实现：

- 中文全拼输入。
- 本地词典驱动的候选生成。
- 候选排序与数字选词。
- 退格、左右移动、上下选择、翻页、取消与提交。
- 中文/英文输入模式切换。
- 中英文标点的基础处理。
- 候选旁可选的简短英文释义。
- 焦点变化和输入法停用时的状态清理。

首期暂不要求双拼、五笔、复杂模糊音、云端联想或基于大型语言模型的候选排序。

## 3. 输入状态机

### 3.1 状态定义

建议使用明确的状态模型，具体 Rust 类型可在实现中调整，但语义不得改变：

- `Inactive`：输入法未激活。
- `Idle`：输入法激活，但没有待处理的组合输入。
- `Composing`：正在输入拼音或编辑组合文本。
- `CandidatesVisible`：存在候选列表且候选窗口可见。
- `Committing`：正在将确认文本提交给目标应用。
- `Cancelling`：正在取消当前组合输入并恢复一致状态。

`Composing` 与 `CandidatesVisible` 可以在实现中合并为单个状态加可见性字段，但必须保留清晰的状态转换和不变量。

### 3.2 状态不变量

1. `Idle` 不得保留上一轮未提交的拼音和候选。
2. 候选列表必须对应当前输入修订版本。
3. 每次输入内容变化后，旧候选结果不能被异步任务覆盖。
4. `Committing` 完成后，组合文本和候选状态必须清空。
5. 取消操作不得向目标应用提交尚未确认的候选。
6. 失焦、停用或目标应用上下文销毁时，必须按平台策略取消或完成组合文本，并清理过期状态。
7. 翻译注释加载失败不得改变候选文本或输入状态。

### 3.3 状态转换

| 当前状态 | 事件 | 结果 |
|---|---|---|
| `Idle` | 输入有效拼音字母 | 创建组合输入，进入 `Composing` |
| `Composing` | 输入更多字母 | 更新输入串并重新生成候选 |
| `Composing` | 候选可用 | 显示候选，进入或标记 `CandidatesVisible` |
| `Composing` / `CandidatesVisible` | Backspace | 删除一个有效输入单位并刷新候选 |
| `CandidatesVisible` | 数字选词 | 提交对应候选 |
| `CandidatesVisible` | Enter | 按本文件规则提交当前候选或组合文本 |
| 任意组合状态 | Escape | 取消当前组合输入，返回 `Idle` |
| 任意组合状态 | 焦点丢失 | 按平台策略取消或安全收尾，清理旧上下文 |
| `Committing` | 提交成功 | 清空组合输入，返回 `Idle` |
| 任意状态 | 输入法停用 | 停止接收事件并释放上下文资源 |

具体平台可能要求不同的系统调用顺序，但最终可见行为应一致。

## 4. 按键处理规则

### 4.1 普通字母

中文模式下，合法拼音字母加入当前输入串。输入发生变化后，核心重新解析并生成候选。解析和候选查询必须在本地完成，不等待翻译服务。

非法字符的处理必须确定且可测试。不能默默丢弃用户字符；如果该字符应作为普通文本输入，应提交或交由平台默认行为处理。

### 4.2 Backspace

- 组合输入非空时，删除末尾一个输入字符并重新解析。
- 删除后为空时，关闭候选窗口并返回 `Idle`。
- 组合输入为空时，不应误删目标应用中已经提交的文本，应将事件交回系统或按平台规则处理。
- 删除过程中到达的旧候选或旧翻译结果必须被忽略。

### 4.3 Space

中文组合输入存在候选时，Space 默认选择当前高亮候选并提交。

没有候选但仍有可提交的原始组合文本时，应按明确规则提交原文或取消，不能无提示地丢失输入。该规则需在首个 Windows 原型中通过真实应用验证后冻结。

在英文模式或没有组合输入时，Space 应按系统正常行为输入空格。

### 4.4 Enter

- 候选列表可见且存在高亮候选时，提交当前高亮候选。
- 没有高亮候选但存在组合文本时，按照已冻结的回退策略提交原始文本或取消。
- 没有组合输入时，Enter 交由目标应用处理，不得被输入法吞掉。

平台实现必须防止同一次 Enter 事件既提交候选又触发目标应用额外换行。

### 4.5 数字键

候选窗口显示编号时，数字键 `1` 至 `9` 选择对应候选。数字键 `0` 的行为必须在设置或产品规范中明确；首期默认不将 `0` 作为第十候选快捷键，避免与正常数字输入冲突。

没有候选窗口时，数字键必须按普通输入行为处理。

### 4.6 方向键与翻页

- Up / Down：移动高亮候选。
- PageUp / PageDown：翻页。
- Left / Right：首期采用明确的一致策略；可用于移动拼音光标或交回系统，但不得因平台不同而出现不可解释的候选错位。
- 用户翻页后，当前高亮索引必须落在有效范围内。

若输入文本变化、候选数量变化或上下文改变，候选索引应重置或夹取到有效范围，不能指向不存在的候选。

### 4.7 Escape

Escape 取消当前组合输入并关闭候选窗口。它不应删除目标应用里此前已经提交的文本。

### 4.8 Shift、Caps Lock 与模式切换

首期提供明确的中英文模式切换。具体快捷键应可配置，默认键位需在原型测试后冻结。

Caps Lock、Shift 与字母大小写必须按系统和输入模式一致处理。快捷键实现不得影响目标应用本来应收到的修饰键组合。

## 5. 拼音解析规范

### 5.1 输入模型

核心保留原始字母串，并生成一个或多个合理的拼音分段候选。拼音解析结果不直接等于最终中文候选；解析器提供分段与匹配信息，候选模块再结合词典生成文本候选。

### 5.2 第一阶段要求

- 支持标准全拼输入。
- 支持连续输入多个音节。
- 支持不完整音节的中间状态。
- 支持删除后重新解析。
- 对歧义分段采用可重复、可测试的规则。
- 对无法解析的输入返回明确状态，而不是崩溃或无限回溯。
- 对超长输入设置合理上限，防止异常输入造成无界计算。

### 5.3 后续扩展

模糊音、简拼、双拼和用户自定义规则应作为独立配置或解析策略扩展，不得改变现有全拼的既定行为。每种方案需要单独的测试语料和兼容性说明。

## 6. 候选生成

候选生成器接收拼音解析结果、词典查询结果和必要的上下文，输出去重后的候选集合。

候选生成必须满足：

- 不执行网络请求。
- 不调用大型翻译模型。
- 对相同输入和相同本地数据产生确定性的候选集合。
- 同一候选文本按明确规则去重。
- 候选项保留来源信息，便于调试与学习。
- 候选数量受配置和性能预算限制。
- 查询失败时仍能返回安全的空结果或回退候选。

如果多个拼音分段映射到同一候选，应合并或按确定性规则保留最佳匹配，不得重复显示相同文本。

## 7. 候选排序

首期排序以本地、可解释、可测试为原则。建议考虑：

1. 拼音匹配完整程度。
2. 音节分段与词条读音的匹配程度。
3. 基础词频。
4. 用户本地选择频次。
5. 最近使用信息。
6. 可选的轻量上下文因素。

不允许候选排序依赖在线翻译是否返回。翻译注释不得直接作为候选得分，避免网络质量影响输入结果。

排序器必须有稳定的平局处理规则，例如匹配分数、词频、词条长度和稳定 ID 的组合。规则需在 `candidate-ranking` 相关设计中记录并通过固定语料测试。

## 8. 候选注释行为

候选注释为可选显示字段，默认只显示简短释义。注释可以来自本地词典或本地缓存。

要求：

- 注释不属于候选提交文本。
- 注释查询不能阻塞候选出现。
- 候选先显示、注释后补充时，必须确认输入修订版本和候选 ID 仍匹配。
- 注释过长时截断或在独立面板展示。
- 同一个候选在当前显示周期内不应因后台返回重复闪烁。
- 用户可以关闭注释显示，但关闭注释不应关闭基础输入。

第一阶段不默认在每次按键时调用在线翻译。候选注释优先使用随包词典和本地缓存。

## 9. 提交与组合文本

核心返回的候选文本与平台最终提交的文本必须一致。平台层负责调用系统接口完成组合文本更新和提交。

提交前需要验证候选仍属于当前输入修订版本。提交成功后清除当前组合状态；提交失败时记录不含敏感输入内容的诊断信息，并按平台能力恢复或提示用户。

必须测试：

- 候选提交后是否重复提交。
- Enter 是否额外换行。
- Space 是否重复插入空格。
- 失焦后是否残留旧候选。
- 快速输入时是否提交过期候选。
- 多行编辑器中组合文本是否被错误覆盖。

## 10. 中英文模式

### 中文模式

字母输入用于拼音解析；候选确认后提交中文词条。候选旁可显示英文释义。

### 英文模式

字母按正常文本输入。首期可选择性提供英文词典注释，但不能影响英文字符上屏。英文单词和短语翻译可以先通过独立翻译面板完成，候选注释的完整支持按路线图推进。

### 模式切换

切换模式时必须定义当前组合输入的处理方式。首期建议：用户明确切换时先安全取消当前未确认组合，再切换模式，避免同一串输入在两种模式下被误解释。

## 11. 失焦、停用与异常恢复

焦点变化、目标窗口关闭、输入法停用或后台服务崩溃时，平台适配层与核心必须完成状态同步。

- 不把上一个应用的候选显示在新应用中。
- 不把上一上下文的翻译结果显示在新输入中。
- 不因翻译进程退出而关闭输入法核心。
- 不保留失效的候选索引或任务句柄。
- 对平台无法确认是否成功提交的情况，应避免盲目重复提交。

## 12. 学习与隐私

学习功能只记录实现排序所必需的数据，例如候选选择次数和最近使用时间。默认不保存完整输入历史。

用户应能关闭学习、清除学习数据和管理用户词典。学习数据应与日志分开存储，并采用可迁移的版本化格式。

## 13. 输入行为验收清单

- [ ] 全拼输入生成预期候选。
- [ ] 连续快速输入不丢字、不重复提交。
- [ ] Backspace 在组合输入和普通文本状态下行为正确。
- [ ] Space、Enter、数字选词行为一致。
- [ ] Escape 取消组合而不误删已提交文本。
- [ ] 候选翻页和高亮索引始终有效。
- [ ] 模式切换不残留旧组合状态。
- [ ] 候选注释不会进入上屏文本。
- [ ] 旧的异步结果不会覆盖新的候选。
- [ ] 焦点切换后不显示旧候选或旧翻译。
- [ ] 翻译服务不可用时仍可正常输入。
- [ ] 在真实 Windows 文本框和多行编辑器中完成验证。

## 14. M2 原型行为补充

M2 宿主明确采用原文回退、拼音光标编辑、每页5条、当前页数字选词、0作为普通数字、基础中文标点与提交成功/失败确认协议。详见 [实现约定](m1-m2-design.md)；这些规则的真实 Windows 行为仍需 M3 验证。41条手写事件语料与候选排序已建立，结果见 [回归报告](reports/m2-candidate-ranking.md)。
