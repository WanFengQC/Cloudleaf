# 云笺算法评估规范

- 文档版本：1.0，2026-10-22。
- 对应任务：CL-005，承接 [核心算法设计](algorithm-design.md)。
- 状态：定义评估数据、分母、对照实验及选型门禁；实际数据集/程序/结果必须在资源清单和报告中登记，不能由本文替代实验。

## 1. 当前证据与评估层次

M1/M2 的41条手写事件序列负责固定行为回归，64条原型词典负责模块组合测试。它们可以验证已列举的预期行为，不能证明真实词频、复杂歧义、长句、生产词典或上下文算法成熟。旧性能报告仅覆盖原型规模和核心同步函数。

评估分为四层，结果不能互相替代：

| 层次 | 目的 | 数据与完成含义 |
|---|---|---|
| 事件回归 | 编辑、取消、选择、提交和生命周期正确 | 保留41条基线并按缺陷扩展；不是语言准确率样本 |
| 独立种子评估 | 校验指标实现、发现能力缺口、建立可重放对照 | 项目手写并登记来源/版本；小样本、非代表性，不支持成熟度结论 |
| 正式算法评估 | 数据分层、独立评测与算法选型 | 授权清晰、有覆盖与样本量依据；训练/开发/测试隔离 |
| 产品全链路评估 | 系统输入、真实应用、端到端与长期资源 | 成熟核心、词库和平台适配组合后的测量 |

本轮建立独立种子集及历史候选基线的可执行报告，只比较 `production-rules-v1` 与 `frequency-only-ablation-v1`。后者仅移除Exact优先，按frequency降序、文本字数降序、稳定ID升序排序；二者使用相同词典、有限解析结果和每桶前50个唯一文本组成的匹配池，再取前50个去重候选。消融后的最终候选/来源可以变化，比较不更改生产输入引擎。

这只是“精确匹配优先规则”的排序消融，不是新候选算法、整句搜索或学习实验；DAG、候选格、加权模型、N-gram、上下文重排与纠错比较均未运行。未来结构性词条格实验如果不含语言转移，只能证明覆盖和工具可行，不能称为成熟整句算法。

## 2. 数据单元和资源清单

每个算法样本至少记录：稳定ID、版本、来源/许可、类别、意图分组ID、split、输入方案/配置、原始输入、已确认左上下文、可接受输出集合、是否含错误、期望纠正（若有）、未知词标记和评价任务。事件样本另保存事件序列、光标/选区和提交期望。

上下文不足以唯一决定同音输出时，要么保存可接受输出集合，要么标为歧义样本，不能把开发者随意选定的一个词当作唯一真值。多义词和词条读音由数据来源与标注规则解释；有争议样本隔离登记，不静默删除。

资源清单记录文件SHA-256、schema、条目数、来源、许可、取得/制作方式、清洗版本、划分方法与划分校验。词库、语言模型和评估集分别登记；人工词频不得冒充统计语料频率。

### 2.1 训练、开发与测试隔离

- train：训练词条转移或模型参数。
- dev：选特征、权重、阈值、Beam宽度与超参数。
- heldout：配置冻结后统一运行，报告真实分母；禁止看答案后修改权重、词频、规则再继续使用同一份测试集宣称独立收益。
- regression：既有事件用例与从已见失败提取的固定行为用例，与独立测试分开报告。

手写种子集必须标明“已见/未用于调参”及限制；开发者知道样例内容，不等同盲测。没有train/dev样本时如实记录为空，不把同一文件复制或改名成三份。后续训练必须引入新的隔离数据版本。

划分按意图/句子来源家族进行，不能只随机打乱行。相同句子的拼音形式、前缀、错字、音节边界、上下文变体放在同组；同一来源段落及近重复句分在同侧。避免正确样本在train、其单字交换错误在heldout造成泄漏。

防泄漏检查至少包含：规范化输入、上下文及可接受输出集合的完全重复；与41条回归相同的任务；同意图家族跨split；来源/句段近重复。重叠样本标记 `regression-overlap` 并从独立heldout分母排除，不能只更换ID。词典本来包含目标词不等于标签泄漏，但观察测试答案后增词、改频率或更换词典必须登记新实验，不能沿用原选型结论。

### 2.2 覆盖类别

| 类别 | 至少覆盖的情形 | 必须拆分的指标 |
|---|---|---|
| 高频词/短语 | 常用单字、词语、固定搭配 | Top-1/5、频率分层 |
| 多音节/长串 | 多字词、跨词条句子及不同长度 | 覆盖、Top-1/5、P95/P99、预算触发 |
| 分段歧义 | 连续拼音、多种合法切分、显式撇号 | gold分段/候选保留、错误切分 |
| 同音/多义 | 可接受集合和多上下文意图 | 分组Top-1/5与上下文收益 |
| 不完整输入 | 末音节前缀、尾部分隔、删除后恢复 | 前缀召回、误补全 |
| 错字/模糊音 | 插入、删除、替换、交换、独立配置 | 纠错precision/recall、误改率 |
| 混合输入 | 中文/英文、数字、标点、快捷键 | 行为正确率、重复/丢失文本 |
| 编辑/连续事件 | 中间插入、左右光标、连续退格/取消 | 状态不变量、全量/增量等价 |
| 低频/OOV | 词典覆盖内低频、覆盖外词及专名 | IV/OOV分别统计、原文保护 |
| 上下文依赖 | 相同拼音在不同已确认前文 | 上下文使用与无上下文消融 |

种子数据尚未覆盖的类别必须列为缺口。不能把未实现能力从正式产品范围删除来抬高指标，也不能用数个手写长句代替真实分布。

### 2.3 本轮种子集与重放入口

数据路径为 `tests/evaluation/algorithm-v1.tsv`，按手写意图group划分dev与heldout，不含train，不训练或调参；准确条数、字段格式和SHA-256以实际资源清单为准。种子采用比上述通用规则更严格的隔离：规范化输入若与既有41条事件语料重复，不作为独立评估输入。对于完全未知词、超出当前原型能力的句子、纠错和上下文任务保留gold与失败，不用改gold的方式迁就原型。

统一入口是Python标准库脚本，它构建并调用Rust `cloudleaf-evaluate` 二进制执行实际候选计算；Python只整理评估，不进入产品输入路径：

```text
python scripts/evaluate_algorithms.py --output-dir docs/reports/algorithm-v1
```

评估程序和脚本的具体输出以生成产物为准；必须含每例结果、分组/总体指标、排序变化、版本指纹和能力缺口。生成报告之后，不允许回改种子gold、原型词频或规则再把同一heldout称作未经查看的测试。

## 3. 指标定义和分母

先对最终候选文本去重，再计算名次。只按任务约定归一候选，不自动简繁转换、不自动删除标点/空白、不以语义“差不多”算命中。输入规范化与输出判定使用不同规则，版本随报告保存。

令 `N` 为本实验冻结测试划分中所有有效的候选任务样本数。每个样本有可接受集合 `G_i`，候选序列 `C_i`。无法解析、超限、无词条及生成空列表在总体候选指标中记为未命中，不能从分母删掉。纯生命周期/透传任务不进入候选分母，另按行为指标报告。

| 指标 | 定义 | 需要同时报告 |
|---|---|---|
| Top-1准确率 | 第一候选属于 `G_i` 的样本数 / `N` | 分子、分母、空列表及错误数 |
| Top-5召回率 | 前5个去重候选至少一个属于 `G_i` 的样本数 / `N` | 不足5个按实际列表；本指标是样本命中率，不是所有相关词条的集合召回 |
| MRR@K | 每例首个可接受候选在前K中的倒数名次，未命中为0，再对 `N` 平均 | 固定K、首次命中名次及无命中数 |
| gold分段保留率 | 至少一条可接受分段仍在解析/搜索结果中的样本数 / 有分段标注样本数 | 裁剪前后、长度分层、精确/前缀分开 |
| gold候选覆盖率@K | 预定任务的可接受文本进入前K路径的比例 | 与词典覆盖、整句覆盖及最终排序分开；不是非空候选率 |
| 非空候选率 | 至少返回一个候选的样本数 / `N` | 只有候选不等于覆盖gold；本轮报告字段名为 `candidate_availability` |
| 词典IV覆盖率 | gold能由允许词典资源表示的样本数 / `N` | 整词存在、合法跨词条路径存在分别报告 |
| 回退保护率 | 回退或超限任务中原始输入完整保留且未误提交的样本数 / 对应回退任务数 | 原文回退不算中文候选命中 |

OOV目标、无模型、无上下文等情况在总体中保留，并另外报告IV/OOV及能力子组；不允许只报覆盖内准确率。当前算法不支持的上下文、纠错等目标标为能力未实现，保留明确的目标覆盖缺口，不能无解释跳过样例。

本轮工具的 `gold_coverage` 指任一gold进入完整有界候选列表的样本比例（上限50），`candidate_availability` 仅指非空候选比例。`lexicon_known` 只检查完整gold文本是否存在于冻结的原型词典，不代表当前输入可检索到它，也不代表跨词条句子可生成；它与通用规范中的整词/路径覆盖分别解释。

### 3.1 纠错评估

设错误标注子集为 `E`，正确输入控制子集为 `V`。系统需要输出可判定的纠错动作/路径信息，而不能仅凭最终中文与标签相同就声称发生了纠错。

- 纠错precision：提出了纠错且恢复到标注可接受目标的错误样本数 / 所有提出纠错的样本数；分母包含对正确输入的误改。若分母为0，结果为null/未定义，不能写成100%。
- 纠错recall：成功恢复到可接受目标的错误样本数 / `|E|`；没有纠错能力的样本不能从 `E` 排除。
- 正确输入误改率：在 `V` 中发生不允许纠错且改变既定目标的样本数 / `|V|`。
- 另报按编辑类型、编辑距离、方案开关的统计，以及“文字命中但纠错轨迹不明”样本数。

本轮两个baseline明确声明 `correction_capability=false`，其实现不进行纠错且纠错动作数为0。因此precision分母为0，结果为null；有 `required` 错误任务时，recall按已知0次成功/错误任务数记为0，并标明“停用基线的已知零动作，不是纠错算法效果测量”。正确输入误改率也只说明这个停用基线没有纠错动作，不能据此宣称某种纠错算法可靠。错误输入的文本Top-1/5仍可独立计算。

上述0只适用于经过核实的无纠错实现。未来模型若仅返回文本、纠错动作/能力信息未知，precision/recall必须为null并说明动作接口缺失；不得把未知解释为0次动作，也不能仅凭文本命中就归因为纠错成功。

### 3.2 排序变化和上下文

逐样本记录历史/实验首个可接受候选名次、Top-5集合与顺序、首选文本变化、改善/退步/持平及其类别。排序变化本身不一定是正确性改善，候选集合变大也不证明语言质量提升。

上下文试验至少比较同一候选器的“无上下文”和“有上下文”两种配置。相同输入的多个意图上下文使用等权家族汇总，避免重复变体放大总体收益。隐私模式、上下文不可读和用户关闭时使用明确的无上下文策略；不能回填其他样本的上下文。

## 4. 实验矩阵和选型依据

| 实验ID | 对照及改变 | 当前可得结论 | 所需后续证据 |
|---|---|---|---|
| E0 历史基线 | 原型解析/词典与规则排序 | 只证明已运行版本在登记数据上的成绩 | 独立种子分母、词典/源码/参数指纹 |
| E0a 排序消融 | 同匹配池移除Exact优先，其余频率/字数/ID规则相同 | 仅判断该规则在登记种子上的作用，不代表候选器或语言模型改进 | 逐例名次变化、分组指标及固定词频快照 |
| E1 结构搜索 | 同词典下整词查询对比有界词条格 | 未实现或未运行时不得填比较数字；无LM仅验证结构覆盖 | 全输入路径、去重、预算和每例名次 |
| E2 可解释加权 | 固定候选器，加入版本化匹配/频率/结构特征 | 待开发集调参和独立集验证 | 消融、权重来源、IV/OOV/长串变化 |
| E3 N-gram | 比较词/字/混合粒度与平滑/回退 | 待授权语料、训练与模型审查 | 未见集效果、OOV、载入/峰值内存 |
| E4 上下文重排 | 固定首轮召回，仅重排有限候选 | 待模型和上下文接口 | 上下文/无上下文消融、隐私关闭路径 |
| E5 纠错/方案 | 独立策略开关，不改变关闭时全拼 | 待实现 | precision/recall、误改率、方案隔离 |
| E6 增量 | 同模型下全量与增量 | 待实现 | 每一事件候选等价、冷/热延迟、内存 |

实验只改变已登记因素。更换词典、频率、样本、归一化、候选上限或模型时作为新的实验版本；不能把它们全部变化后的收益归给排序算法。所有实验状态为“未实现、未运行、已运行待审查、通过、拒绝”之一，失败和无收益也保留记录。

独立种子集用于启动工具与定位缺口，不据此冻结生产算法。正式选型前，先用开发集确定实际准确率目标与样本量，再登记不可被实现随意降低的验收阈值；阈值未冻结、样本无代表性或数据授权未完成时，不放行生产选型。比较报告给出配对样本改善/退步计数及预先约定的置信区间/检验方法，不能只用四舍五入后的小数宣称更优。

## 5. 性能、内存与规模

沿用核心初始延迟预算作为工程目标：P95≤5ms，P99≤10ms；本地候选查询P95≤5ms。它们不是对最终UI的承诺；平台端到端预算要在首轮真实TSF测量后独立冻结。

每次实验记录：系统/CPU/内存、Rust/构建参数、源码/二进制指纹、词典/语料/模型/权重版本、候选和搜索预算、预热、冷启动、样本数、P50/P95/P99/max、进程内存采集方法、峰值及后台负载说明。解析、词典、搜索、排序、帧返回和平台显示分别计量，不能混用单词查询成绩作为整句生成成绩。

规模维度至少包含当前原型、正式词库目标规模、用户词典增长；长度维度包含短词、短句、长串和高度歧义边界。没有合法正式词库时可用登记的合成规模数据测试资源，必须标为合成，不能报告其语言准确率。

压力集包括长时间连续输入、频繁中间编辑/退格、快速取消/失焦、候选翻页、词典/学习快照切换及翻译任务积压。报告搜索预算触发率、回退率、内存增长、队列上限、状态不变量和文本丢失/重复次数。同步输入不得等待网络、模型载入或数据导入。

## 6. 可重复报告与门禁

一次实验的最小报告包含：

1. 实验ID、状态、变更假设、相对baseline版本及单一主要变量。
2. 源码提交/工作树指纹、可执行文件指纹、词典/数据/模型/权重与配置指纹。
3. 实际命令、平台、构建模式、随机种子（若使用）、预算与超时策略。
4. 数据划分/防泄漏检查，整体和分组分子/分母，排除项及原因，null指标说明。
5. 每例候选/名次/行为差异，失败案例和未支持能力；开发中不得仅保留成功例。
6. 性能、内存、冷启动、规模与压力结果，正确性/性能取舍及是否触发回退。
7. 结论、适用范围、未验证范围、采用/拒绝理由及复核人/记录。

自动门禁至少要求资源/划分检查通过、41条历史回归无未解释变化、文本可靠性用例无丢失/重复、结果可重放。增量算法要求全量等价；学习关闭/清除、方案关闭和无上下文路径均有测试。遇到预算退化、低频词明显退步或纠错误改，要提供归因与明确接受标准，不能用整体平均数掩盖。

CL-005 的种子集和基线工具可以先作为“评估基础设施完成”的交付；正式集覆盖、真实统计频率、模型对比和算法成熟度仍按本规范继续推进，不能因为手写样本达到某个数量就标为最终算法验收完成。

## 7. 本轮实测登记

数据为 `tests/evaluation/algorithm-v1.tsv`，83条手工诊断seed（16 dev、67 heldout），train为空、dev未调参；SHA-256与来源见资源清单。运行 `python scripts/evaluate_algorithms.py --output-dir docs/reports/algorithm-v1`，比较E0/E0a，产物见[实测报告](reports/algorithm-v1/report.md)及[本轮验收](reports/cl001-cl006-validation.md)。

heldout的Top-1为31/67、Top-5为37/67；移除Exact优先没有提高这两项，MRR从0.501244降到0.498756。保留本轮固定生产规则，不据此选定未来候选格或语言模型。超限、无候选、未支持能力均未删分母。正式集、E1..E6及生产选型门禁保持未完成。
