# 云笺完整产品范围与验收索引

- 版本：1.0，2026-10-22。
- 目标：输入流畅、候选准确、翻译可靠、功能完整、可长期维护的正式跨平台输入法。
- 状态依据：本地 Rust 源码、64 条手写原型词典、41 条固定事件语料及 M1/M2 验收记录。当前原型不等于正式产品，文档中描述的最终能力不代表已经实现。
- 关联：[开发路线图](roadmap.md)、[算法设计](algorithm-design.md)、[算法评估](algorithm-evaluation.md)、[核心与平台契约](core-platform-contract.md)、[Windows 设计](windows-tsf-design.md)。

## 1. 使用规则

阶段用于管理依赖与质量门禁，不缩减最终功能范围，也不要求所有功能在同一版本一次交付。Windows 系统适配的交付目标包含完整的按键交接、组合文本、候选交互、可靠提交与生命周期；技术验证只能证明接口风险是否可控。

本表的需求 ID 在后续设计、代码、测试、实验报告和任务记录中保持稳定。删除或改变用户可见需求，必须记录原因、风险、替代行为与验收影响。任何项目被标记为“完成”前，均须补齐：设计版本、实现路径与提交、自动化和真实环境测试证据、性能/资源影响、数据与依赖许可、隐私影响及完成日期。

当前状态使用以下含义：

- **原型已验证**：现有有限数据与 CLI/核心测试通过；系统集成、真实规模和完整算法质量未据此验收。
- **部分原型**：已有字段或局部行为，尚不能交付该完整能力。
- **未实现**：无可验收的对应实现；设计或测试计划不是功能完成证据。

阶段索引采用：S0 基线、S1 规格/评估/契约；A Windows、B 核心算法、C 正式数据三方向并行；S2 Windows 全链路集成；T1 词语/短语、T2 整句、T3 离线与自定义服务；S4 质量发布与多平台。详细任务依赖以路线图为准，REQ 是长期需求标识，不随阶段名称变化。

## 7. 当前限制与最终产品参数的区别

以下仅登记现有实现边界，后续必须依据正式数据、支持场景与质量/性能实验重新确定，不能从原型直接继承为永久产品承诺：

| 当前原型边界 | 现有含义 | 正式产品决策要求 |
|---|---|---|
| 最多64个ASCII输入字节 | 避免原型解析无界；原文保留大小写，直接ü尚不规范化 | 明确原始/规范化/显示文本与索引单位，支持合理长输入和安全上限；超限不得静默截断 |
| 每位置及最终最多32条解析 | 歧义路径截断，不能证明保留所有正确路径 | 记录剪枝与预算原因，对照完整小规模搜索及独立语料，评估召回与尾延迟 |
| 输入帧最多50条，候选库硬上限128 | 原型资源限制 | 区分搜索预算、总候选、窗口分页和按需加载；用真实数据确认可配置边界 |
| 每页5个候选 | 原型交互规则 | 结合候选窗口、可读性、可访问性和快捷键确定默认值与配置范围 |
| 64条手写词典、人工整数词频 | 测试数据，不代表真实语言分布 | 正式来源/许可、词频/读音/义项质量及覆盖评估，不用手写数据充当正式词库 |
| 41条固定事件语料 | 行为与排序回归基线 | 保留回归并独立扩展算法评估、上下文/纠错/长句及真实平台测试，避免训练或调参泄漏 |
| 仅词条候选，未知输入回退原文 | 没有整句候选、上下文或学习 | 以全输入候选格、可解释评分与质量对照推进，始终保留可恢复的未知输入策略 |

最终仍需要资源上限；上限应是可验证、可诊断并适合产品场景的工程决策，而非删除安全约束。提高上限也必须验证质量、尾延迟和内存，不只修改常量。
